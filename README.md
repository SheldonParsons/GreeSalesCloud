# 商用订单管理系统测试工作台

本仓库供 Web 测试工程师维护【商用订单管理系统-客户端】和【商用订单管理系统-管理端】的需求分析、思维导图用例、UI / 接口测试证据及交接资料。

## 从这里开始

1. 阅读 [协作规则](AGENTS.md)、[系统范围](context/systems.md) 和 [环境说明](context/environments.md)。
2. 在 [需求索引](requirements/README.md) 找到需求，读取该目录的 `README.md`，确认当前状态和下一步。
3. 编写用例前阅读 [用例规范](context/test-cases.md)；访问知识库前阅读 [工具与知识库映射](context/tools.md)。
4. 按 [需求流程与交付约定](context/workflow.md) 推进，正式交付围绕测试用例、知识库内容和用户临时指定的产物。

具体需求采用一个会话对应一个需求；本项目另保留治理会话，负责流程审计、改进提醒和框架维护，不在其中开展具体需求任务。一个需求涉及两端时，共用需求目录，在分析、用例和执行记录中区分系统。关键结论应及时落到项目文件，交接不依赖聊天记录。

现行流程为 **试行基线 v0.1**，待通过实际需求逐步验证。阶段复盘与规范更新方式见 [流程治理](governance/README.md)，已知问题和改进状态见 [改进记录](governance/improvements.md)。

## 资料放置原则

| 位置 | 内容 |
| --- | --- |
| `context/` | 跨需求通用的系统、环境、工具和用例约定 |
| `governance/` | 流程审计方式、改进证据、试行和采纳记录 |
| `requirements/<需求编号>/` | 本期材料、分析、用例、执行结果和知识同步记录 |
| `templates/` | 新需求起步模板 |
| `regression/`（按需创建） | 经评审可复用的核心回归场景 |
| `scripts/`（按需创建） | 可复现的测试脚本及运行说明 |

Git 保存分析过程、版本和执行证据；知识库保存确认后的可复用业务知识；思维导图作为正式测试用例的主要展现形式。三者通过需求编号、文件路径和知识条目引用关联，避免出现多个来源不明的版本。

密码、Token、Cookie、完整会话和未脱敏业务数据不得提交。临时原始证据放在被忽略的 `.local/` 中，选取必要且脱敏的证据后再纳入需求目录。
