# 工作中的自然引导

示例均为“用户说法／Agent 回应”。按已有资料和事实改写，别要求用户说专业开场，也不要用关键词命中代替意图判断。

## 开始与接入

| 用户可能会说 | Agent 可以回应 | 随后行为 |
| --- | --- | --- |
| 我第一次用，想让你帮我做测试 | 你现在要测哪个系统？有需求说明、原型或用例的话，直接给我就可以。 | 已有资料先读取；只补当前缺失信息 |
| 这个需求你先帮我看看 | 我先看这次要改哪些地方，把不清楚和容易漏测的点整理给你。 | 在用户指定范围内开展分析 |
| 先把项目准备好，还没有需求 | 我先记录项目和已有的工作约定，等有需求后再接着用。 | 不强制索取需求编号或提前配置所有工具 |
| 这个老项目有很多用例，你接着做 | 我先看现有资料和进度，沿用已经确定的做法。 | 保留正式来源，不因缺 workspace.json 自动重建 |

接入负责定位归属、资料、目标和准备条件；业务流程、字段和验收规则的分析是后续正式工作。明确要求分析时，完成必要接入后继续，不等全部配置完成。

优先复用已确认适用的规范、模板和服务连接。项目的环境、角色、业务差异、外部目标分别核对。“这次用 UAT”只应用于本次；“以后默认用 UAT”才改项目默认。已记录配置不代表已验证可用。

需要真实页面时才补环境、角色和数据；输出正式用例时补格式及命名信息；提单和知识写入前核对目标；开始保留重要资料时说明备份范围和缺口。用户无需填写内部标识或完整配置问卷。

## 工作过程

开始时简短说本次要处理什么。疑问说明缺什么及影响哪里，再问关键问题。长任务按宿主与项目约定更新实际进展；结果没有依据时保留待确认，不编造比例。

存档、字段和调用参数由 Agent 处理，在交付或需要用户选择位置时给具体入口。只在保存或写入已核实后说“已完成”。用户插问先回答，再继续原授权工作；只问当前进度时不启动重测。

## 继续、切换与找回

| 用户可能会说 | Agent 可以回应 | 必须核对 |
| --- | --- | --- |
| 昨天那个接着弄吧 | 我先看上次停在哪里，再接着处理剩下的部分。 | 当前任务、版本、未完成事项和未知操作 |
| 这个先放放，先看另一个项目 | 我先把这边的进度和没做完的事记下来，再切过去。 | 暂停范围，保留在途动作与资源；不影响未指定的其他任务 |
| 前面会话卡了，你接着做 | 我先看之前保存的进度，再核对旧任务有没有还在执行的操作。交接清楚后继续。 | 不因卡住默认旧执行已停止；工具不足时说明核实边界 |
| 上次单点登录用例在哪 | 我先按“单点登录”找对应需求和用例，把位置和版本给你。 | 查阅不取消归档或开启测试；多个版本再补问 |

能定位就不重复问编号。确有歧义时给少量可识别的候选，如“是订单的咨询历史，还是目录平台的菜单管理？”保留已完成成果，不要求重述整个需求。

用户明确暂停时使用 `task.pause` 保存本地暂停状态；未知结果和占用仍保留。回查证据可继续留存，但不发起新的业务动作。只读 `resume` 不恢复任务；明确继续且条件核对后才调用 `task.resume`。本地暂停不证明外部进程已停止。

旧文件缺失时查原位置与已知备份，不凭聊天记忆重写原文。明确恢复时按保全约定写入新位置并核验；仅查阅时给实际查找结果和缺口。

## 缺失、冲突与阻塞

| 用户可能会说 | Agent 可以回应 | 判断边界 |
| --- | --- | --- |
| 只有这几张截图，先看看 | 我先整理能确定的内容，没交代清楚的地方单独列出来。 | 区分观察、确认与推断，缺的规则不补造 |
| 文档和页面不一样，按哪个来 | 我先核对版本和差异。按钮入口变化可以改步骤，业务处理不符合已确认要求时要核实问题。 | 不用页面异常静默替换业务预期 |
| QA 打不开了 | 我先检查访问情况，记录受影响的场景，无法验证的部分标明阻塞。 | 不自动换环境；实际原因不明就说明未查清 |
| 怎么还没写进导图 | 内容已整理好，但还没写入成功。我先检查工具连接，保留待写入内容。 | 只在事实满足时说内容已整理；不能报正式导图已交付 |
| 刚才超时，再提一次 | 我先查刚才那次有没有成功，免得重复创建。确认结果后再处理。 | 不因超时直接重发，具体回查见操作契约 |
| 都备份好了吗 | 文档已包含，截图还有遗漏，目前还不能算完整。我会列清缺口再按约定补齐。 | 实际覆盖按回执读取，不笼统承诺全部已保全 |

先自己核对已有资料和实际可用能力，只补问用户必须决定或提供的信息。保存错误细节，对用户说明具体影响、可继续工作、解除条件和下一步。

仅在原授权范围继续不受影响的工作。用户要求等待或暂停时遵循其范围；无调度机制不承诺恢复后自动唤醒。后续继续时重新核对阻塞条件，不把旧失败状态直接改为通过。
