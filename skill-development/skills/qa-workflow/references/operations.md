# 状态与协作

## 恢复

`resume` 显式指定项目、需求，已知任务时指定 task。检查阶段、范围、共享版本变化、运行统计、未知操作、资源和快照警告。有 `next_task_offset` 或 `details_truncated` 时按范围展开；统计只覆盖已分配场景，不代表全需求用例齐全。

快照核对只证明文件未变化。继续业务前还需核对环境、角色、单据和材料版本；本工具不读取浏览器或推断登录态。

## 分工和结果

协调者 `task.create` 分配范围、运行批次与场景。同一批次重叠场景不能同时分配给活跃任务。分析任务可省略批次与场景。

通过 inputs 固定已经保存的用例或来源快照，通过 context 保存环境、构建、角色引用、数据引用及参与系统。未固定来源的执行任务会有 INPUT_VERSION_UNPINNED 提示；真实业务执行前须补齐依据。后续记录保留当时输入与上下文，凭据正文不进入这些字段。

执行者维护自己的结果。协调者读取 `run.summary`、`resume` 后核对覆盖，更新阶段，按需生成 `summary.write`。用例按批次和场景去重，BUG 引用另行去重，重试不算新增用例。

`case.record` 记录结果、证据快照和具体依据；通过、失败必须有证据。工具核对登记和完整性，真实性、断言和归因由执行与审查负责。阻塞、未执行不能标通过。

`case.sync` 登记实际核对过的产物写入回执，不调用 Mind。先用真实工具写回并回读，将回执留存快照，再由执行者或协调者登记。测试结果和同步完成分开保存。

## 资源与未知写操作

同一真实资源使用一致标识，如 `mind:<文档身份>`、`browser:<上下文>:<页面>`、`business:<项目>:<环境>:<单据>`。工具不识别不同字符串其实指向同一资源，也不阻止绕过协调的外部程序。

1. `resource.acquire` 取得本任务占用与资源修订。
2. `operation.prepare` 保存意图、目标、回查线索和资源修订；不保存请求秘密。
3. `operation.dispatch` 持久化待核实状态。收到成功回执后，才按授权调用实际业务工具一次。
4. 超时先回查，保留待核实；不能重派发、转移任务或释放相关资源。
5. 保存实际回查证据，用 `operation.resolve` 登记 confirmed 或有依据的 not_applied。
6. 完成后 `resource.release`。资源释放再获取后，旧准备记录不能继续派发。

`operation.dispatch` 返回 `external_action_executed:false`，表示它没有发业务请求。HTTP 200 也不代替业务状态回读。

## 交接与冲突

旧执行者停止新动作，处理未知操作并释放资源，保存待办与证据。协调者 `task.transfer` 记录已核实的停止事实及交接说明；存在未知操作或占用时拒绝转移。停止字段不是自动停止宿主进程的开关。

新执行者再 resume。原负责人标签不能继续修改已交接任务；单纯复制文件不会自动获得当前业务执行权。

`task.finish` 可关闭、暂停或阻塞。关闭表示任务结束，不表示用例全部通过。明确交接可再次开启，不自动复测失败用例。

更新必须使用已读取的 `expected_revision`。冲突时重新读取并比较，在授权范围内合并；不要取最新修订号后直接覆盖旧内容。

文件写入通过短时锁和原子替换串行提交；业务资源占用跨命令保留，不因超时自动过期。这些都是协作约定，不是安全租户或身份认证机制。
