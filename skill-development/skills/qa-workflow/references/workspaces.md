# 项目接入

先理解当前任务和已有资料。只接入项目时，定位归属、资料入口和当前目标；用户明确要求分析时，完成必要准备后再开展分析。环境、角色和工具到相关工作需要时核对，不要求用户先理解内部配置。自然表达和渐进配置见 [工作中的引导](interaction.md)。

## 新工作空间

`workspace.init` 在已授权的目标目录创建 `workspace.json` 和 `.qa/`，不迁移目录、修改 Git、安装 MCP 或启用全局 Skill。

使用稳定的小写标识定位，中文名称用于显示。需求编号可作为标识；缺编号时用明确的临时标识，后续保留映射。不要从同名推断对象相同。

```text
工作空间/
├── workspace.json
├── shared/<条目标识>.json
├── projects/<项目>/
│   ├── project.json
│   └── requirements/<需求>/
│       ├── state.json
│       ├── tasks/<任务>.json
│       ├── operations/<操作>.json
│       ├── artifacts/<快照>.json
│       ├── runs/<批次>/<场景>.json
│       └── README.md                 # 协调者按需生成
├── artifacts/<内容摘要>/<文件名>     # 明确导入的留存快照
└── .qa/                             # 历史、派生索引、资源和写入协调
```

格式 v1 使用 JSON，避免 YAML 运行依赖。摘要标注生成时间与来源版本，最新状态通过 `resume` 核对；不要把摘要作为另一份可编辑状态。

## 已有项目

沿用现有正式用例、规则、BUG 目录及知识库。可在选定的独立目录试用基础状态管理，并记录正式产物来源。`artifact.import` 留存某一时刻的快照，其 `source` 指向原文件，不取代正式来源。Mind 文件仍通过原 MCP 编辑，不离线重写。

本版尚无通用旧目录自动迁移或完整外部路径映射配置。逐项登记已授权资料并报告未覆盖部分，不能声称已接入所有历史。

## 项目与系统

项目各自保存系统映射，如 orders 下的 client、admin。需求归牵头项目，systems 可引用其他已登记项目的系统。同号需求必须带项目标识，跨项目参与不复制主记录。

coordinator、owner 是本地协作标签，可关联真实会话引用，不是服务端认证。每次任务请求显式传递项目、需求、任务，不使用跨会话共享的“当前项目”指针。

## 共享与差异

`shared.publish` 保存适用范围、来源、正文和修订。只有 config 可声明允许覆盖的默认字段；业务规则冲突先核对确认。

`shared.attach` 固定项目引用的修订与差异。新发布不替换旧引用；`shared.resolve` 和 `resume` 提示变化。任务创建时保留当时引用，恢复时核对。

共用实现的适用条件和真实结果仍按项目记录。本版只保存引用与配置，不执行共享正文中的代码或指令。
