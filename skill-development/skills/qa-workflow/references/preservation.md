# 信息保全

## 记录和快照

每条记录带格式、修订、前一版本摘要及完整性摘要。更新先留历史，再原子替换当前记录。历史不自动删除；手改 JSON 会触发完整性错误，应先保留现场并查历史。

`artifact.import` 只读取明确授权的文件，保存快照、摘要、来源、时间和用途。新内容用新的快照标识保存。快照是留存依据，原导图或其他正式来源仍通过其原工具维护。

含敏感内容时标为 `sensitive:true`，当前实现不自动识别所有秘密。备份是本地明文 ZIP，目标应符合用户保管要求，不上传或自动纳入 Git。

## 检索与归档

`list` 默认每页 20 条，最多 100 条，按项目、编号或关键词定位。索引可从权威记录重建，缓存不作为唯一来源。

`requirement.archive` 只改标记，不删除或移动。须先处理活跃任务、资源和未知操作；原失败、阻塞状态不变。`include_archived:true` 查历史，明确重新开启后再工作。

## 备份范围

`backup.create` 包含受管状态、历史和已登记快照。目标在工作空间外且不能已存在；这不证明已跨设备或异地保存。

原文件后续变化、未登记文件、凭据、浏览器会话和未导出的外部服务数据均不自动备份。正文引用的图片须分别登记，不能只存 Markdown。

敏感、缺失或损坏快照默认使备份拒绝。明确 `include_sensitive:true` 才包含敏感快照；`allow_partial:true` 可保存带缺口清单的部分备份。`complete_for_registered_snapshots` 只对登记范围成立，须同时检查 exclusions。

`backup.verify` 核对清单、摘要、格式和快照关系，不证明所有业务资料已登记，也不代替恢复演练。

## 恢复

`backup.restore` 只写尚不存在的新目录，拒绝覆盖原资料，校验路径、重复条目、摘要和非常规文件；当前解压体积上限 2 GiB。失败保留未完成标记，原备份不改动。

1. resume 核对资料、附件、历史版本和缺口。
2. 确认源执行者已停止，回查未知操作，处理占用资源。
3. 有依据时由维护者 `restore.activate`；仍有未知操作或占用则拒绝。
4. 重新核对当前环境与身份，不重放备份中的历史业务动作。

恢复副本保留原逻辑身份。不能同时激活源与副本操作同一对象；本版不能跨机器强制停止原执行者。

## 故障处理与限制

- INTEGRITY：保留损坏文件，查历史或备份，不重新计算摘要掩盖变化。
- WORKSPACE_BUSY：lock.inspect 给出锁位置。先核实原主机和进程已停止、没有并行写入，再由操作人员处理残留锁；本版不自动删锁。
- IO_ERROR：可能已有部分保存，先回读目标，不重放业务请求。
- RESTORE_INCOMPLETE：保留失败目录，在另一个新目录核验恢复，不直接取消标记后继续。
- UNSUPPORTED_SCHEMA：保留数据并停止写入。本版只实现格式 v1，尚未交付跨格式自动迁移。

Git 只覆盖已纳入的文件，不能证明仓库外导图与截图已备份。本版没有定时任务或后台巡检；报告最后实际检查和恢复点，不承诺零丢失。
