# 整体设计

更新时间：2026-10-31。文档状态：设计基线；具体实现结构仍为提议。

## 定位与确认边界

已确认目标：制作可复用的测试工作流 Skill，以人性化引导支持从需求分析到缺陷修复验证的工作，并兼容多会话。

用户已同意使用本仓库 `skill-development/` 作为开发目录。`qa-workflow` 名称、下面的细分文件、配置格式和状态模型尚未定稿。

Skill 的工作范围由用户当次任务和已确认的项目约定决定。用户可以直接进入已有用例执行或指定 BUG 的处理，不强制从需求分析重新开始。

## 标准与交付形式

公开格式依据：[Agent Skills Specification](https://agentskills.io/specification)。前一轮讨论已读取原文；发布前需再次核对规范。

- 一个 Skill 是一个包含 `SKILL.md` 的目录。
- `SKILL.md` 使用 YAML frontmatter 加 Markdown 正文，标准必填字段为 `name`、`description`。
- `name` 与 Skill 目录名一致。版本可放在标准的 `metadata` 映射中，使用字符串。
- 脚本、参考资料、模板分别按需要放入 `scripts/`、`references/`、`assets/`。
- ZIP 是公司平台的交付封装要求，标准 Skill 的基础是解压后的目录及文件。

示意入口（提议，尚未创建实际 SKILL.md）：

```yaml
---
name: qa-workflow
description: 引导 Web 测试人员完成需求分析、页面取证、用例编写、执行、缺陷处理和修复验证，支持接续已有测试任务。
metadata:
  version: "0.1.0"
---
```

交付建议：维护标准源码目录；生成用于上传的 ZIP；在开源仓库中提供使用说明、验证材料和选定的许可证。名称、许可证、发布范围及上传时机另行确定。

## 公司平台已观察到的要求

来源：[公司 SkillHub 上传页](https://tsc.gree.com:30230/skillshub/skills/new/)。前一轮通过 Chrome DevTools 只读查看了页面及文件控件，未上传文件。

| 项目 | 已观察到的内容 | 适配判断 |
| --- | --- | --- |
| 文件 | 单个 ZIP，页面标注最大 50MB，包含 SKILL.md | 按平台限制打包 |
| 元数据 | frontmatter，页面只明确列出 name 必填 | 我们仍填写标准要求的 description |
| 示例 | 顶层 version、dependencies | 不将平台示例扩展视为标准字段；优先 metadata.version，依赖用实际语言清单与兼容说明表达 |
| 依赖文件 | 支持 requirements.txt、package.json | 页面没有证明会自动安装或成功执行依赖 |

尚未确认：ZIP 是否要求单层目录、标准元数据能否完整解析、附属目录是否完整保留、依赖如何执行、平台如何分发到目标宿主。后续以实际最小包核验，不能根据上传页宣布全面兼容。

## Skill 包结构提议

```text
skills/qa-workflow/
├── SKILL.md
├── references/
│   ├── onboarding.md
│   ├── guidance.md
│   ├── collaboration.md
│   ├── project-scope.md
│   ├── shared-resources.md
│   ├── state-contract.md
│   ├── data-lifecycle.md
│   ├── stages/          # 各测试环节的规则与完成依据
│   └── integrations/    # 浏览器、导图、知识库、缺陷平台、配套 Skill
├── scripts/
│   ├── workspace/       # 必要的工作目录与状态操作
│   ├── adapters/        # 已验证的平台操作封装
│   └── lib/             # 共享函数
└── assets/
    ├── templates/
    ├── schemas/
    └── examples/
```

入口直接指向当前阶段所需文档，避免逐层搜索长引用链。只加载当前任务需要的阶段说明和工具契约；执行稳定脚本时以简洁结果为主，不反复读取全部源码。

阶段拟覆盖：需求接收与分析、页面取证、用例编写、评审、执行、缺陷处理、修复验证、知识沉淀、收尾。知识沉淀可在多个阶段发生，不必等测试结束。

函数和外部依赖应说明：使用时机、输入输出、环境要求、副作用、失败与结果不明时如何处理。工具名称可做平台映射，但不存在的适配器不能被描述为已支持。

配套 Skill/MCP 的引用不等于安装或授权；使用前检查实际可用能力。首次接入不要求连接所有工具，只在任务需要时补齐依赖。第一版支持范围仍待确定，不承诺兼容所有浏览器、导图和缺陷平台。

## 用户测试工作目录提议

```text
Agent 工作目录/
├── README.md
├── workspace.yaml                # 被测项目索引及位置映射
├── shared/                       # 有适用范围和版本的共享内容或来源引用
├── projects/
│   └── 被测项目标识/
│       ├── project.yaml          # 本项目的系统、环境、工具目标映射
│       ├── context/
│       └── requirements/
│           └── 需求编号/
│               ├── README.md
│               ├── state.json
│               ├── sources/
│               ├── analysis/
│               ├── cases/
│               ├── runs/
│               ├── bugs/
│               ├── knowledge/
│               └── handoffs/
└── .local/                       # 本机资源按项目、环境和任务区分
```

这是新工作空间的候选结构，补充支持一个 Codex、WorkBuddy 等 Agent 项目承载多个被测项目。被测项目可包含客户端、管理端等多个系统。身份、状态及跨项目协作详见 [多项目隔离与任务状态](project-scope.md)。

现有项目优先沿用其真实目录与外部产物引用，通过索引映射到对应被测项目。避免将外部正式用例或 BUG 文件复制成另一份权威版本；本次设计更新不迁移当前仓库的历史目录。具体配置格式、字段和同步实现待定。

多项目共享的规范、模板、业务知识和工具能力保留一份权威来源，项目引用适用版本并记录自身差异。Skill 内置方法、工作空间共享内容、项目专属内容分开维护；具体机制见 [共享内容与项目差异](shared-resources.md)。

目录按实际工作逐步创建。配置中使用账号引用，凭据留在本机合适位置。运行日志、会话数据和业务证据不写入通用 Skill 安装目录。

状态与产物须有明确对应关系：用例存在不等于已评审，单个 BUG 复测通过不等于整套用例通过，工具成功不等于业务结果正确。[状态与恢复](state-contract.md) 的原则已确认，结构化状态和人可读摘要的一致更新机制尚未实现。

长期使用与信息保全是贯穿各环节的目标。资料需保留来源及历史依据，增长后可按需检索，备份覆盖仓库内外必要产物，升级须保留用户数据；候选措施与待确认项见 [长期维护与信息保全](data-lifecycle.md)。本轮不迁移、清理或备份真实资料。

## 引导和多会话提议

对话规范的核心为：说明当前进度、推荐下一步、只收集影响本步的信息、解释必要问题的用途。示例话术表达沟通目的，不要求每次机械复述。

支持单会话，也支持需求主会话和执行会话分工。会话绑定被测项目与具体任务，不能依赖一个全局“当前项目”指针。一个需求涉及多个平台时保留统一牵头记录，明确参与项目、系统及各会话负责的场景和产物。

共享状态应关联材料及用例版本、证据、尚未完成的工作、结果不明的写操作和下一步。[多会话协作](collaboration.md) 的分工、资源协调及交接原则已确认；具体字段和机制仍待实现与验证，不能只靠说明宣称已解决并发。

创建会话、发送消息、持续监控取决于宿主工具和用户授权；标准 Skill 本身不保证这些能力。不具备会话工具时提供手动交接开场。模型选择、Git 策略、系统地址和人员映射属于项目配置，不能把本项目所有偏好写成所有用户的通用规则。

## 逐环节设计约定

每个环节分别确定：入口、输入、Agent 动作、产物、完成依据、衔接与恢复方式，并检查长期保存、历史引用及升级兼容要求。当前进度统一以 [推进计划](../roadmap.md) 为准。

验证计划应覆盖首次使用、已有项目接入、缺少工具、信息冲突、多会话交接和未知写入结果。格式校验、实际行为验证、公司平台上传兼容分别确认，不互相替代。
