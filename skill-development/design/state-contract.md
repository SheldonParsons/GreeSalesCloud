# 状态与恢复

更新时间：2026-10-31。状态：1.3 原则已确认，本地状态、历史和恢复已有 [0.1.0 实现与验证](../implementation-v0.1.md)。下面记录设计原则；实际字段与限制见包内契约。

## 已确认的原则

用户在“用例编写中换会话”“测试执行中断”“BUG 提交后超时”三个例子的讨论后，明确要求按该方案记录。

1. 分别记录工作进度、业务结果和同步情况。
2. 恢复时核对依据，从明确的未完成事项继续。
3. 结果不明的写操作先回查，避免重复执行。

状态应帮助接手者回答：已经完成什么、依据在哪里、哪些还没确认、下一步怎么继续。产物和测试证据是核对依据，状态文件的一句“已完成”不能单独证明业务完成。

## 要区分的状态

| 对象 | 示例 | 判断边界 |
| --- | --- | --- |
| 阶段和任务进度 | 需求分析已完成、用例编写中、待评审 | 文件存在不等于内容完整或已经评审 |
| 测试结果 | 未执行、通过、失败、阻塞 | 完成的用例须关联操作与结果证据，缺数据不标通过 |
| 业务写操作 | 准备提交、已发出但待核实、结果已确认 | 超时不能直接等同失败，也不能直接重发 |
| 产物同步 | 结果已保存、导图标记待同步 | 同步失败不自动推翻已核实的测试结果 |
| 缺陷和知识工作 | BUG 待提交或待修复、知识待同步 | 不由单一测试阶段字段推断完成 |

这些是概念区分，尚未指定正式枚举或 schema。同一需求可同时有“用例已评审、测试部分完成、BUG 待修复、标记待同步、知识库待更新”等状态。

## 需要保存的信息

保存所属工作空间、被测项目、需求与当前任务；在已有授权范围内说明本次工作边界。状态记录本身不新增权限。

需要关联的内容包括：

- 已确认规则、来源及尚未解决的问题。
- 当前材料、共享规则和正式产物的位置与版本。
- 已完成范围、未完成事项、阻塞原因和解除条件。
- 执行环境、角色引用、必要业务数据标识、测试结果及证据位置。
- 失败场景与 BUG 的关联，避免将失败场景数直接视为 BUG 数。
- 已发出但尚未确认的操作、目标与可用于回查的信息。
- 导图标记等产物同步是否完成，以及下一步。

状态保存摘要和引用，完整用例、截图、BUG 正文留在对应产物位置。凭据使用引用，原始会话与敏感运行数据遵循本机存放约定。读取恢复资料时按需展开，不把所有历史证据一次加载进上下文。

## 三个已讨论的例子

以下进度为机制示例，不是当前真实需求的执行结果。

### 用例编写中换会话

以 71652 为例：需求分析已完成，查看场景已写，审批场景未写完，一条业务规则待确认，导图已保存但尚未评审。

保存已确认规则、导图位置与版本、已完成分组、待确认规则的影响和剩余工作。新会话先核对这些资料，再继续审批场景；不重新要求用户描述全部需求，不自行补造未确认的预期。

恢复说明示例：

> 查看场景已经完成，审批场景尚未补齐。我会继续编写审批部分；那条未确认规则仍保留为待确认。

### 测试执行中断

假设本轮共 20 条用例：8 条通过、2 条失败、1 条阻塞、9 条未执行。两个失败场景若属于同一个已核实问题，应保存 2 条失败用例与 1 个 BUG 的关联。

同时保存用例版本、环境、角色、每条结果与证据、关键业务数据标识及导图同步状态。恢复时核对这些条件是否仍适用，再继续明确的未完成事项；不会仅凭旧状态断言新版本仍通过。

若测试通过且证据已保存，但导图标记写入失败，应保留“结果已确认、标记待同步”。恢复时核对并补写标记，不因同步失败自动重新执行业务操作。失败场景的修复验证仍按明确复测任务推进。

### BUG 提交后超时

已发出创建请求但未收到确认时，保留“结果待核实”。关键写操作发出前保存目标、内容版本及回查信息，结果核实后补充实际结果。

接手者按原目标和本次提交记录回查；找到对应 BUG 后记录编号并继续核对字段与图片。未能确认时保留待核实，不把未知结果直接当成失败而重复建单。审批、创建业务数据和知识库写入适用同样原则。

## 保存与恢复时机

Agent 在以下节点主动保存：重要结论确认或一部分产物保存完成时；每条用例执行完成时；关键写操作发出前及结果核实后；遇到阻塞、切换任务、准备交接时。

突然中断后依靠最近保存的记录回查现场，不保证未保存的动作已被完整记录。状态与实际文件或页面不一致时先核实，保留不确定部分，避免重复写入或误报完成。

人可读进度摘要与结构化记录应保持一致。[多会话协作](collaboration.md) 已明确执行者记录、主会话汇总和交接原则；具体冲突检测、锁实现及文件格式仍待设计。长期版本留存、备份与升级见 [长期维护与信息保全](data-lifecycle.md)，不把单次中断恢复视为全部数据已备份。

## 后续实现需验证

1. 已确认规则和已保存用例可被新会话定位，未确认内容不会自动变成定论。
2. 执行结果、证据、BUG 关联及待同步标记能够分别恢复。
3. 用例或规则版本变化时能说明影响，不无依据沿用旧结果或重写历史。
4. 已发出的未知写操作先回查，避免重建 BUG 或重复审批。
5. 状态与实际产物不一致时能识别并保留待核实状态。

原则确认后，0.1.0 已生成虚构状态并完成本机恢复验证；没有据此修改真实业务结果，也没有实现外部平台自动同步。
