# asynctest-kb 信息获取与 Agent 接入引导

更新时间：2026-10-31。状态：已收到用户的知识库 MCP 页和下载菜单截图，并在浏览器核对下载菜单；图文指引与标注素材已纳入 0.2.1。安装、完整凭据流程、MCP 接入及新会话图片显示仍待验证。

## 用户明确的分工

主要引导用户在 Asynctest 的实际位置取得 MCP 连接信息并交给自己的 Agent。客户端适配交给当前 Agent 检查与处理，不默认用户使用 Codex。

用户提及 WorkBuddy、Codex 作为可能使用的客户端，同时表示尚不确定。它们只是候选验证对象，不是默认入口，也不表示当前已经验证兼容。

## 通用路径

1. 未安装时，打开 [文档页](https://nexofolio.net/docs)，悬停页头 AsyncTest，选择 Gree 内部版或公网版，再选择目标电脑的 Windows x64、macOS Apple Silicon 或 Intel 包。
2. 使用自己的账号进入 AsyncTest，在设置页“个人”区域选择“知识库 MCP”。主界面进入设置的具体操作本轮截图未展示，后续真实会话补充取证。
3. 服务地址区域可复制当前服务地址，截图显示 Streamable HTTP。需要凭据时按“当前凭证”中的“创建凭证”获取自己的完整 Token；已有可用凭据可复用。
4. 向下查看“客户端连接配置”，截图可见 Codex、Claude、通用配置三个页签。复制适用的完整模板，不因截图选中 Codex 就固定采用该客户端。
5. 将实际复制的连接信息交给当前 Agent，说明希望接入的知识项目。
6. Agent 优先从运行上下文、可用工具和既有配置识别宿主，按授权适配；已有连接可用则复用。配置后用实际工具的只读调用核对项目身份与可读范围。

已确认标签与字段见 [实际图文指引](../../skills/qa-workflow/references/asynctest-setup.md)。版本与地址以当前页面为准；创建凭据弹窗、完整配置正文和各客户端适配方式未在本轮操作验证，不补造未见的参数。

用户可直接这样表达：

> 这是我从 Asynctest 复制的知识库连接信息，帮我接入，并确认能读取我要用的项目。

截图用于说明去哪里获取信息；真正接入优先使用用户复制的配置文本，避免依靠截图识别长地址或认证值。

## Agent 的适配责任

- 先检查实际宿主和当前能力，不假设所有 Agent 都能自动修改配置。能在授权范围完成时自行处理，保留已有连接和其他设置。
- 确需用户登录、授权或手动操作时，只说明当前必要的一步；宿主无法确定时再补问名称与版本。
- 用户交付连接信息用于接入，不等于授权创建、修改或删除知识内容。
- 读取配置不能证明当前会话已经能调用工具；工具可见也不能证明目标知识项目可读。验证结果分层报告，不只看全局开关。
- 验证连接优先采用指定范围内的只读查询；项目没有知识时如实报告已验证的项目读取范围，不为证明连接自动写测试知识。
- 认证信息按宿主提供的安全方式配置，仅留在约定的本机或受控位置，不写进通用 Skill、Git 或知识正文。
- 需要具体客户端说明时，再读取其适用版本的官方文档或实际界面。客户端附录按需增加，主引导保持通用。

## 接入后的用途与边界

需求分析时读取适用历史知识，帮助补足概念、对象关系、现行规则和过去变更；不把召回结果直接当成本期已确认规则。

本期完成、正式上线且用户确认短期稳定后，强烈推荐将最终知识正文保存到 asynctest-kb。让用户知道收益：后续少重复解释、方便跨会话和人员交接、识别相关回归范围，并保留规则来源与版本。

知识库读取、连接配置、最终知识写入分别按实际范围推进。未接入时本地轻量记录仍可支撑当前工作；不将外部服务设为开始澄清的硬门槛。

## 后续验证

- 将 [真实会话图片展示计划](../../verification/image-display-plan.md) 纳入后续验收。先验证 Codex 是否能在最终回复区实际展示截图，不推断只有 Codex 支持，也不自动启动新会话。
- 当前制作会话的图片预览、包内资源存在、新会话独立显示和其他宿主兼容分别记录，不能互相替代。
- 根据真实会话补齐设置入口、凭据弹窗和配置正文；已核对字段不重复要求用户提供。
- 检查“只想了解”和“明确接入”是否区分，纯说明不会更改客户端配置。
- 读取现有连接时不重复索取信息；客户端能力不足时能给出具体、最少的补充步骤。
- 用只读调用核对正确项目及权限范围，不自动执行知识写入。
- 明确哪些宿主和版本实际验证过，哪些仅有通用设计，不能把一个客户端成功推广到全部 Agent。
