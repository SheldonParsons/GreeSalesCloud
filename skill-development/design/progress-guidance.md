# 工作过程中的自然表达

更新时间：2026-10-31。状态：2.3 表达与引导约定已由用户确认；尚未写入实际 Skill 或完成独立体验验证。

## 确认记录与原则

用户指出“本次先梳理需求中的业务规则、影响范围和待确认问题……”不像用户会说的话。明确该句原为 Agent 回复示例后，用户确认采用自然表达，并要求按“用户会说的话／Agent 回应”继续设计。

采用以下约定：

1. 用户自然表达目标并提供已有材料，无需先说出阶段名称、内部字段、目录结构或正式测试术语。
2. Agent 结合请求与已有资料识别阶段，组织步骤并保存记录；只有关键缺失会改变工作时才补问。
3. Agent 的回应也用日常语言，简短说明接下来做什么；不把内部维护动作逐项念给用户。
4. 有必要时在交付处给出产物位置和状态，保存成功后才声称已记录。
5. 进度和结论以实际依据为准，已授权工作连续推进；表达自然不等于省略影响判断的条件、缺口或风险。

## 用户与 Agent 的成对示例

下列是目标对话方式，不是本轮正在执行的真实测试。

| 用户可能会说 | Agent 可以回应 | 随后实际需要做的事 |
| --- | --- | --- |
| 这个需求你先帮我看看 | 我先看这次要改哪些地方，把不清楚和容易漏测的点整理给你。 | 读取需求与项目已有规则，梳理范围和关键疑问 |
| 这份用例有没有漏的 | 我对着需求检查一遍，看看哪些场景没覆盖，步骤能不能照着做。 | 核对覆盖和可执行性，保留问题依据 |
| 上次没测完，接着测吧 | 我先查上次停在哪里，再接着处理剩下的部分。 | 读取进度并核对当前条件、授权与未知操作 |

示例说明表达目的，不要求逐字套用。同一句“帮我看看”需结合材料和上下文理解，不能固定映射成任意业务写操作。

## 四个沟通时机

| 时机 | 要让用户知道什么 | 表达要求 |
| --- | --- | --- |
| 开始工作 | 当前要处理的范围和下一步 | 一小段即可；已有清楚指令就直接接上 |
| 遇到关键疑问 | 缺什么依据、影响哪里、需要用户决定什么 | 用易回答的问题补齐，说明用途，不让用户重述已知背景 |
| 工作进行中 | 实际完成、剩余和阻塞 | 遵循宿主与项目更新约定，给有信息量的进展，不虚构比例或反复播报空话 |
| 本轮交付 | 产物入口、已确认结果、未完成事项及下一步 | 区分局部完成与整体完成，按现有授权继续或保留待办 |

术语和实现细节在帮助用户做决定或用户主动追问时展开。通常由 Agent 处理稳定标识、调用参数和文件维护；用户需要查看产物或选择路径时再给出具体位置。

## 后续检查

- 对话示例始终标清用户和 Agent，避免把专业开场当成用户必须提供的指令。
- 简短表达仍能说明工作范围，不因口语化擅自增加执行、提单或知识库写入。
- 存在关键歧义时实际补问；已有资料能够回答时先查资料。
- 进度具有依据，未知结果明确保留；文件和同步位置仅在实际成功后报告。
- 多会话与长期使用下，简洁回复背后仍有可持久读取的记录，不能用口头承诺代替保存。
