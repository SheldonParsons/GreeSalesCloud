# 多会话协作

更新时间：2026-10-31。状态：1.4 原则已确认，本地任务、资源登记及交接校验已有 [0.1.0 实现](../implementation-v0.1.md)。真实宿主派发和外部工具强制互斥未接入。

## 已确认的原则

用户在分工执行、共享资源冲突、旧会话交接三个例子的讨论后，明确回复同意。采用以下约定：

1. 每项任务有明确负责人和产物范围。
2. 独立任务可以并行，相互影响的操作协调执行。
3. 执行者维护自己的记录，需求主会话核对并汇总。
4. 交接先核对旧任务和现场，再转移执行责任。

简单任务可以由单会话完成。实际新建会话、委派执行、跨会话消息及监控依赖宿主能力和授权；确认协作原则不代表本轮已授权创建或启动执行会话。

## 分工执行的例子

以 71652 为例，需求主会话负责业务规则、范围、分配和结果审查；两个执行会话分别负责指定的客户端独立场景、管理端独立场景。每项任务说明项目与需求、用例版本、场景范围、环境角色、产物位置和当前负责人。

执行会话维护自己的运行记录、证据及本地 BUG，主会话读取后核对覆盖和结果，再更新总进度。汇总以对应场景与执行记录为依据，不能直接相加重复或重试次数。不同需求分别维护自己的主要会话与状态。

“客户端创建 → 管理端驳回 → 客户端修改 → 管理端查看历史”保留为一条完整场景，由一个任务负责完整链路，或明确交接同一条咨询单。各端完成一部分不能被统计成两条完整场景通过。

## 共享资源冲突的例子

两个执行会话准备写同一份导图时，明确一个当前写入负责人；其他会话先保存结果和证据，由负责人核对场景及版本后写回，未同步的内容继续保留待同步状态。

需要协调的资源包括同一导图、浏览器页面或登录会话、正在修改的业务单据、共用角色和仍在使用的测试数据。不同标签页不代表业务对象和账号状态独立。

资源占用说明示例：

> 这份导图正在由另一个执行会话更新。我已保存当前结果和证据，标记暂列待同步，先继续不依赖该资源的工作。

并发操作本身是被测目标时，应作为明确任务统一设计。资源登记、版本核对和互斥写入的实现仍待后续验证，聊天约定本身不提供执行层强制隔离。

## 旧会话交接的例子

1. 核对旧任务是否仍在执行；能够正常交接时，旧执行者停止新动作并保存现场。
2. 整理已完成场景、证据、待办、数据标识、页面状态、待同步产物和结果不明的动作。
3. 核对未完成写操作及资源状态；不能仅凭旧会话长时间没有回复认定其已停止。
4. 新会话核对后接手，更新当前负责人，从明确未完成事项继续。

原执行者可能仍操作同一资源时先解决冲突。未知提交按 [状态与恢复](state-contract.md) 回查，不能重复派发相同写动作。

接手说明示例：

> 旧会话的已完成结果和证据会保留。其中一次提交尚未确认，我会先回查，再继续后面的场景。

## 宿主能力与用户体验

用户可以表达工作目标与分工，不需手动维护内部任务字段。在具备相关工具且已授权的宿主中，由 Agent 执行派发与交接；缺少这些能力时，提供任务说明、开场话术和资料入口用于手动接续。

没有自动化时不声称主会话持续监听、自动醒来或实时汇总。模型和会话分工按具体项目约定配置，不能将某个模型固化成所有使用者的要求。

## 后续实现需验证

- 分工范围和写入责任可追溯，汇总不会重复计算场景。
- 导图、业务对象、角色和数据冲突能够被识别与协调。
- 旧执行者未停止或存在未知写动作时，不会直接启动重复操作。
- 交接后产物、版本和证据仍可定位；不依赖旧会话永久可用。
- 并发状态更新能发现版本冲突，而不是最后一次写入覆盖其他成果。

0.1.0 已完成本地协作登记的虚构验证；未创建真实执行会话、委派业务任务或实现自动宿主协作。
