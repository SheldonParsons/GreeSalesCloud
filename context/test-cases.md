## 推荐结构

```text
需求编号 + 标题
├── 公共前置条件 / 数据准备
├── 客户端或管理端（跨端时区分）
│   └── 功能
│       └── 场景
│           └── 操作
│               └── 可核对的预期结果
└── 待确认问题（与正式可执行场景分开）
```

- 保留现有“步骤下挂预期”的写法；公共条件集中说明，场景特有条件就近记录。
- 同一操作下可列多个明确检查点。预期或执行结果不同的输入情况，应能分别标记结果；避免用大量斜杠合并后无法知道哪种情况已测。
- 用例应明确角色、关键输入、动作和预期业务状态。提示文本、数据保存、列表变化或审批流转等检查按需求实际涉及的内容选取。
- 场景层可采用 `69772-TC-001` 这类稳定编号，以便关联 UI / 接口记录和缺陷；用例调整后避免把已有编号重新分配给不同场景。
- UI / 接口验证是执行方式，可关联同一业务场景，不为凑数量重复列出相同用例。
- 正常、异常、边界、权限、状态流转、跨端一致性和历史缺陷回归按需求相关性选取，不机械套用所有类别。
