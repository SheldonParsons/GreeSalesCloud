## 账号 Token 分发

2026-11-27 用户指定[账号 Token 分发会话](codex://threads/01a21aca-3f50-7581-9355-b963fb76bb87)集中处理账号 Token：其他会话将登录需求交给该会话，由其执行用户指定的 `/Users/sheldon/Documents/GithubProject/GreeProject/scripts/qa-session.mjs`，将对应结果交还原请求会话。用户的授权覆盖这一流程所需的跨会话请求和回传；不扩展为其他消息、业务测试或权限变更的授权。账号、角色和菜单权限问题仍由上方的 QA 统一用户管理平台专责会话处理。

1. 请求注明原会话链接或 ID、用途或需求、环境、目标应用、账号或账号引用，以及本机授权材料的路径或其他可用的安全存储引用。具体凭据与 Token 通过本机受限存储交接，不提交到 Git，也不放进知识库、日志或普通交接消息；同机共享时可使用被 Git 忽略的 `.local/` 下专用目录，目录权限 `0700`、文件权限 `0600`。这些权限不能隔离同一操作系统用户下的会话；不假定其他主机能访问本机路径。
2. 分发会话按脚本当前 `--help` 和请求准备输入，以标准输入传入授权信息，输出由管道或 socket 接收；不要在命令参数、终端输出或日志中暴露授权材料。脚本核对返回身份后，按环境、应用和账号把所需访问 Token 交付至本机受限存储，向原请求会话回传其引用及必要的身份和有效期信息；不默认交付刷新 Token。临时副本在到期或确认不再需要后清理。
3. 同一份刷新授权串行使用。成功且返回轮换后的刷新 Token 时先更新原本机安全存储，再处理该授权的下一次请求；若授权可能已轮换、身份未确认或结果未知，先核对状态，不盲目重放。缺少授权、配置或需人工验证时说明阻塞，不把结果标为成功。

2026-11-27 首次试领使用了 72844 的 QA 商用管理端账号。分发会话调用脚本一次，原请求会话收到了 `authorization_required` 回执（`business_refresh_provider_not_registered`，退出码 2）。本次调用停在本机路由检查，未向平台发起刷新请求。成功签发后的受限存储交接和请求方身份回读仍待验证。

同日核对的脚本支持范围如下，使用时以实际版本为准。

- `qa` / `iam` 支持密码或刷新授权。密码方式除用户名、密码外还需要获准使用的 OAuth Basic 客户端授权、`deviceKey` 和已实际确认的 `agreementAccepted: true`；刷新方式需要该账号的刷新 Token。若平台要求人工验证，脚本会返回需人工处理。IAM 的 `uat` 未注册。
- 当前脚本的商用管理端 `commercial_admin` 和客户端 `commercial_client` 路由只实现标准 OAuth 刷新授权，要求 `GREE_QA_OAUTH_ROUTES` 内有可信令牌地址、OIDC 用户信息地址、客户端和账号主体映射，以及该账号的刷新 Token；机密客户端还需客户端密钥。仅有账号密码不能通过此脚本获取商用端 Token，不能据脚本支持推断平台已支持该套协议。
- 2026-11-27 核对 NexoFolio 商用订单管理系统测试环境的“获取业务订单系统 OAuth 令牌”：保存的历史观察中，刷新场景使用 `refreshToken` 查询参数和含 `grantType`、`requestTime` 的 JSON 请求体；该接口另有 Basic 请求头观察，其是否适用于本账号刷新尚未确认。字段关联、客户端授权、必填性和刷新策略仍未确认。这与当前脚本的表单刷新及 OIDC 身份回读方式不同，不能把观察直接当成已确认的续期契约或写入可执行路由。已查到的管理端 `getUserInfoForConsult/{id}` 按指定用户 ID 查询，并非已确认的当前令牌主体接口；成功签发及身份回读均未验证。
- 脚本返回的是认证会话，不自动证明浏览器已登录或账号具备业务权限；被测流程要求真实单点登录时仍按该流程执行，不用 Token 注入替代。
