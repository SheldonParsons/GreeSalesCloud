# 用例编写骨架

依据 [思维导图用例范式](../context/test-cases.md)。本文件是编写参考，正式用例仍通过Mind维护；不要把占位符当作实际数据或已验证的页面内容。

```text
文件：{版本号}版本_{需求概述}_lb_{发版日期}.amind

需求概述
└── 需求概述（需求编号）
    └── 按业务流程命名的分组
        └── 具体条件或操作＋应出现的结果
            ├── 准备：环境、角色及权限、起点、单据状态、数据来源
            ├── 1．本步骤的业务目的
            │   ├── 操作：角色／平台，在【页面／区域】对【组件】做什么，输入什么
            │   └── 应看到：能独立核对的文字、数据、身份或状态
            ├── 2．下一步骤的业务目的
            │   ├── 操作：使用上一步取得的真实标识定位对象，执行明确动作
            │   └── 应看到：……
            └── 结束处理：结束状态、记录的标识及必要数据处理（按需）
```

## 写前核对

- 已知版本号、需求概述、需求编号、发版日期、目标路径及文件范围；未知项明确指出，不猜。
- 本次允许编写全量、部分还是仅示例；本期已确认规则和待确认事项分别是什么。
- 是否有现行文档、用户未保存修改、已归档限制或同编号的其他专项文件。

## 准备与数据

| 项目 | 需具体到的内容 |
| --- | --- |
| 平台／环境 | 目标入口、环境，页面未核实时明确标记 |
| 角色 | 账号角色、该单所需实际权限；凭据按项目规则在本机使用 |
| 起点与状态 | 登录状态、入口或完整公共流程引用、目标单据当前业务状态 |
| 输入 | 具体文字、数值或附件内容；示例数据与需求事实分别说明 |
| 标识绑定 | 输入参数来自哪个准备步骤；创建成功记录哪个真实标识，后续如何复用 |
| 多角色 | 哪一步切换到谁、哪个平台；如何隔离会话并核对账号 |

## 交付前自查

- 折叠到分组和标题后，首次阅读者能沿业务顺序讲解，标题无冗余用例编号。
- 展开后步骤有顺序、有可定位的页面组件、有具体输入和就近检查，不依赖口头补充。
- 公共流程引用完整可定位；所需真实数据绑定、角色、结束状态清楚。尚未核实的执行信息没有冒充已验证事实。
- 普通场景能独立检查结果；跨角色场景有完整输入输出交接。预期不同且需独立判定的情况没有混成一条。
- 保留用户已确认业务规则、覆盖、删减、密级、优先级和真实执行证据；保存及回读结果有记录，未执行不标通过。
