# 技术咨询单基础规则：咨询单与子单、状态、时间字段及组织归属

## 适用范围与依据

- 拟维护项目：商用订单管理系统-管理端。
- 知识类型：本次需求讨论中确认的既有业务背景，可供后续技术咨询单需求复用；并非全部由需求 69772 新增。
- 整理基准：2026-09-20 用户说明、客户端/管理端列表及状态截图、需求 69772 的最终澄清。
- 涉及客户端的内容用于说明单据来源和两端共同数据模型；本次只拟在管理端项目维护，不表示已向客户端知识库同步。
- 本文记录业务规则和材料观察，不证明当前环境已通过测试。状态枚举可能随后续需求变化。

## 1. 咨询单、咨询卡片与咨询子单

用户在客户端创建咨询单，一次创建可以填写多张咨询卡片。

| 对象 | 含义与关系 |
| --- | --- |
| 咨询单号 | 一次创建成功后形成的整张咨询单标识 |
| 咨询卡片 | 创建时填写的单张咨询内容，一次可有多张 |
| 咨询子单号 | 按卡片数量生成的子单标识，一张卡片对应一个子单 |

一次创建 3 张卡片，会形成 1 个咨询单号和 3 个咨询子单号。客户端和管理端的咨询单列表均以咨询子单号拆分显示，同时可以展示对应咨询单号。

同一咨询单下，各咨询子单独立接单、独立审批，可以同时处于不同状态。不能因其中一个子单完结，就把同一咨询单下其他子单也判为完结。

需求 69772 的报表统一以咨询子单为统计单位。符合统计条件的 3 个子单计 3 单，不能按共同咨询单号合并成 1 单；同一子单重复符合多个可见范围条件时也不能重复计数。

## 2. 审批流程与节点配置

咨询单从客户端创建后，经历接单和审批。审批流程在 CRM 中配置，审批节点和审批对象均由该配置决定；咨询子单按相应流程审批。

正常审批流程走到最后，咨询单状态为「已完结」。已完结不能直接解释为作废或无效。

本次讨论明确区分以下两个节点：

| 节点 | 已确认的用途 |
| --- | --- |
| 商技部技术人员答复 | 独立的审批节点；其累计答复时长用于需求 69772 的技术部答复周期 |
| 商经部技术人员核对 | 独立的审批节点；其实际「答复」事件用于总部按时答复率判断 |

这两个名称不是同一节点的两种写法，不能相互替换。「商经部技术人员答复时间」则是本期平均接单周期公式明确采用的时间字段称谓，不能因指标名称含“接单”而改用接单时间，也不能未经字段映射核验就把所有带“商经部”的字段合并。

### 2.1 核对节点的答复与驳回

用户确认审批流程中一定有「商经部技术人员核对」节点，该节点可选择「答复」或「驳回」。

- 实际执行「答复」才构成总部按时答复率中的已答复事实，使用实际答复时间。
- 执行「驳回」不构成已答复，不能把驳回操作时间当作答复时间。
- 驳回后重新流转到该节点，实际执行答复后，才有该节点的已答复事实。
- 「已答复」在这里是统计判定条件，不据此给列表状态枚举添加一个新状态。
- 驳回不算已答复，不等于驳回前的节点审批耗时被清零。节点累计时长遵循另一套既有规则，见《技术咨询单审批统计：节点时长、驳回次数与跨审批流累计》。

## 3. 当前状态枚举与统计含义

用户提供的当前状态共以下 10 项；这是当时状态列表，不构成完整状态转移图，也不保证未来不会变化。

| 状态 | 已确认的报表相关含义 |
| --- | --- |
| 待提交 | 满足可见范围和筛选条件时计入咨询总量 |
| 待修改 | 满足可见范围和筛选条件时计入咨询总量 |
| 待确认 | 属于当前状态枚举，按子单及实际筛选条件统计 |
| 待接单 | 属于当前状态枚举，不因未接单而从咨询总量中排除 |
| 已接单 | 属于当前状态枚举 |
| 答复中 | 属于当前状态枚举 |
| 已驳回 | 满足可见范围和筛选条件时计入咨询总量；不属于有效咨询量扣除的三种完结状态 |
| 已完结 | 正常流程结束状态，也是有效咨询量扣除集合之一 |
| 已完结无需非标选型 | 有效咨询量扣除集合之一 |
| 已完结无选型方案 | 有效咨询量扣除集合之一 |

在需求 69772 中，「已完结咨询子单量」特指下列状态集合：

```text
{ 已完结, 已完结无需非标选型, 已完结无选型方案 }
```

有效咨询量等于满足同一统计条件的咨询子单总量，减去上述集合中的子单数量。这是本期指标定义，不能把“有效”自行解释为“所有已经成功答复的单据”。

用户提供的列表截图中，部分已完结记录同时显示评价状态「待评价」。这是两个字段并存的观察，不代表所有已完结记录一定待评价，也没有据此确认评价状态会影响本期统计。

## 4. 时间字段及其区别

| 时间字段 | 已确认含义或使用方式 |
| --- | --- |
| 创建时间 | 与咨询时间不同；需求 69772 不以它作为全局日期筛选字段 |
| 咨询时间 | 本期全局日期筛选锚点；亦为已确认的部分周期及总部时效起点 |
| 销售公司申请时间 | 本期公式中的这一称谓，经用户确认就是咨询时间 |
| 接单时间 | 既有说明取待接单状态变为已接单状态的时间；晚于咨询时间 |
| 商经部技术人员答复时间 | 本期平均接单周期采用的结束时间字段；没有该时间的子单不参与该平均 |
| 商经部技术人员核对的实际答复时间 | 总部按时答复率所用事件时间；驳回操作不能代替 |
| 完结时间 | 对外答复周期的结束时间；该指标按有无该字段确定参与样本 |
| 各审批节点的审批时间 | 既有节点耗时算法的事件边界，不能统一替换为咨询时间 |

### 4.1 咨询时间何时更新

只有**驳回到用户，且用户重新发起**，才重新计算咨询时间。

任意内部审批节点驳回并不自动重置咨询时间。筛选和以咨询时间为起点的指标，应使用该统计对象当前对应的咨询时间。

咨询时间更新与历史审批时长累计是两件事。重发使咨询时间更新，不表示旧审批流中已经产生的对应节点时长自动清零。

### 4.2 已驳回与完结时间的材料边界

旧审批明细字段说明及既有第 3 项规则把已驳回列入达到结束状态后取时间的范围；用户曾对此提出疑问。当前没有实测证明所有已驳回记录一定有完结时间。

本期对外答复周期的最终规则已经明确：**有完结时间就参与平均，没有就不参与，不额外按状态排除。** 因此已驳回若有完结时间则参与，若无则不参与。不能把此规则反写成“已驳回一定有/没有完结时间”。

## 5. 总部、销售公司与科室

### 5.1 总部和销售公司创建来源

现有管理端技术咨询单列表有「销售公司咨询单」「总部咨询单」两个 Tab。

- 销售公司创建的咨询单具有所属销售公司。
- 总部创建的咨询单没有所属销售公司。
- 需求 69772 未选择全局所属销售公司时，包含总部和销售公司子单，仍受其他筛选条件与可见范围约束。
- 选择所属销售公司后，只匹配所选销售公司创建的子单，总部子单自然不匹配该字段条件。
- 总部在公司分析图和公司明细中以「珠海格力电器股份有限公司」展示。
- 图表能显示总部名称，不证明总部子单具有所属销售公司字段值，也不证明全局公司下拉一定提供“总部”选项。

### 5.2 科室归属内部规则

用户确认：一个科室接单后，后续不会再转到另一个科室，这是内部业务规则。

本期按接单科室归属，不构造跨科室转移或同一子单在 A、B 两个接单科室重复计数的业务要求。尚未实测的空科室字段，不擅自解释为必须新增“未分配科室”组或必须排除。

# 技术咨询单审批统计：节点时长、驳回次数与跨审批流累计

## 适用范围与来源

- 拟维护项目：商用订单管理系统-管理端。
- 知识类型：既有审批明细统计规则，是需求 69772 使用的历史业务基础，不应全部描述为 69772 新增功能。
- 主要来源：用户在 2026-09-20 提供的审批明细字段表，以及标题为「3.技术咨询单审批报表计算各个业务节点审批时长：计算各审批节点的审批时长，并进行各审批节点时长统计」的既有需求截图。
- 用户说明这些统计已是现行功能；本次仅核对需求材料与用户解释，未执行现有系统验收。
- 单据/子单及节点背景见《技术咨询单基础规则：咨询单与子单、状态、时间字段及组织归属》。

## 1. 按流程进度展示及归集

技术咨询单审批流配置中包含「流程进度名称」与「排序」。报表据此展示对应表头，并把各审批节点的时长统计到该节点配置的流程进度。

表头格式：

```text
#流程进度名称#时长(小时)
```

归集依据是审批节点与配置流程进度的对应关系，不能仅凭名称相似把两个不同进度合并。

## 2. 单次审批节点的时长

| 节点情况 | 既有规则 |
| --- | --- |
| 已审批节点 | 该节点审批时间 − 上一个节点审批时间 |
| 当前正在审批的节点 | 当前时间 − 上一个节点审批时间 |

时长计算需排除内部日历中的非工作时间，见第 5 节。

关键含义：

- 节点耗时不是统一从咨询时间开始算，而是以上一节点审批时间为起点。
- 当前未完成的节点也可能已有累计时长，不能把“有时长”限定为“已完成答复”。
- 首个节点如何取得上一节点时间、后台如何映射事件，当前材料未另行展开，不自行生成技术实现规则。
- 使用当前时间的统计结果具有查询时点属性；不能把不同查询时点的增长直接判断为计算不一致。

## 3. 驳回后的重复审批和多审批流累计

### 3.1 驳回但单据未完结

单据驳回未完结，驳回节点再次审批也需要计入时长。

对同一流程进度，保留既有发生段与再次发生段，不能只统计最后一次经过节点的耗时，也不能因为其中一次操作是驳回就删除该段时长。

### 3.2 驳回并完结后重新发起

单据驳回并完结，重新发起新的审批流，多个相关审批流都需要计入时长。

因此，若旧流程已有某节点时长，新一轮尚未走到该节点，旧时长仍不能因为“当前这轮还没到”而清零。

### 3.3 与咨询时间更新的关系

驳回到用户并重新发起会更新咨询时间；任意内部节点驳回不自动更新时间。

咨询时间是筛选及部分指标跨度的锚点，而本节是既有节点累计时长规则。更新咨询时间不会推翻多个审批流累计的要求。

### 3.4 与已答复判定的关系

总部按时答复率中，「商经部技术人员核对」节点的驳回不算实际答复。但驳回前经过的审批耗时仍按既有节点算法累计。

**不算已答复，不等于节点时长不统计。** 答复状态判定和节点耗时归集不能共用一个排除条件。

### 3.5 计算示例

以下是规则演算，非已执行测试：某子单在同一商技部流程进度的两次审批中，扣除非工作时间后分别耗时 2 小时和 1 小时，则累计为 3 小时。不能因为第一次是驳回，只保留第二次的 1 小时。

## 4. 单位与计算精度

既有规则要求：多个审批时长相加后，换算为小时，四舍五入保留 2 位小数。

```text
流程进度累计小时 = round(各相关审批段工作时长之和 / 3600秒, 2)
```

这里的公式用秒表达换算关系，不代表已确定后端存储单位。

- 15 分钟对应 0.25 小时。
- 不能把每段先取整小时再累计。
- 也不能把每段先四舍五入到两位小时，再声称等价于全部相加后统一舍入。

规则演算：两段各 20 秒，总计 40 秒，换算后约 0.01111 小时，最终为 0.01 小时；逐段先舍入再相加可能错误得到 0.02 小时。

## 5. 工作日历与非工作时间

既有规则写明审批时长排除周末和节假日。用户进一步确认系统已有内部日历表，包含周六日、节假日和调休配置，应以该表判定工作日。

- 日历中的休息日时长不累计。
- 调休形成的工作日应按工作日累计，不能固定排除所有周六和周日。
- 本次确认的工作日按每天 24 小时累计，不只累计规定上班时段，不按每天 8 小时折算。
- 日历表结构、覆盖年份和具体环境数据尚未读取；存在既有日历功能不等于本轮已经验证节假日计算正确。

## 6. 审批总时长

用户明确采用：

```text
审批总时长 = 完结时间 − 接单时间
```

上述跨度扣除非工作日。

既有第 3 项规则还分别描述：

| 单据情况 | 既有总时长描述 |
| --- | --- |
| 已完结、其他完结类型，以及已驳回的咨询单 | 完结时间（达到对应状态的时间）− 接单时间 |
| 未审批通过的咨询单 | 当前时间 − 接单时间 |

该处原文以「审批总时长（天）」表述。按天展示时，小时与天的换算应保持每天 24 小时的口径。

**来源边界**：旧字段说明将已驳回列为有结束时间的情况，用户曾质疑这一字段是否实际存在。本次没有实测全部已驳回记录的字段值。上述表格保留旧需求适用情形，不得引用成“所有已驳回记录必有完结时间”的数据事实。

需求 69772 的对外答复周期另从咨询时间起算，并按有无完结时间纳入平均，不能直接复用审批总时长数值。

## 7. 驳回次数

按配置的流程进度，统计对应驳回节点的审批驳回操作次数。

旧字段说明包括：

- 商经部答复驳回次数。
- 商技部技术人员答复驳回次数。
- 商经部技术人员核对驳回次数。
- 商经部技术主管审批驳回次数。

当前材料没有单独展开驳回次数的跨流程去重或底层合并方式，不能把“多审批流时长累计”的文字无限扩展成额外计数算法。

# 69772 技术咨询单报表：汇总指标、答复率、周期及环比口径

## 适用范围与依据

- 维护项目：商用订单管理系统-管理端。
- 适用需求：69772【PC管理端】技术咨询单报表可视化图表展示。
- 整理基准：2026-09-20用户最终确认、需求人员提供的第6/7项修订截图，以及原型中未被后续确认替代的单位、环比、精度说明。
- 原型页面可能仍保留旧公式。本文呈现最终确认口径，已撤回的讨论结论不作为并行规则。
- 本文例子是公式演算，非实测报告；未由此确认当前环境已经实现。

## 1. 统一统计集合与时间单位

先对当前账号应用可见范围，再按咨询时间和其他全局条件筛选。把最终入选、按咨询子单号去重的集合记为 `S`。

项目可见范围、字段来源及默认最近30天，主维护于《69772 技术咨询单报表：功能范围、查询条件与数据可见范围》。

为说明公式，本文使用：

| 符号 | 含义 |
| --- | --- |
| `N` | 集合S中筛选后的全部咨询子单数量 |
| `E` | `S` 中不属于三种完结状态的有效咨询子单集合 |
| `N_E` | 有效咨询量，即集合E中的子单数量 |
| `H(t1,t2)` | 从t1到t2、扣除内部日历非工作时间后的小时数 |
| `A` | `S` 中有“商经部技术人员答复时间”的子单集合 |
| `F` | `S` 中有完结时间的子单集合 |
| `D` | 本次日期区间包含的统计天数 |

符号是本稿的说明记法，不是后台接口字段或数据库列名。

### 1.1 工作日历

时效及已确认周期扣除非工作日，使用既有内部日历表的周末、节假日和调休配置。一个工作日按24小时累计，不按每天8小时，也不机械排除所有周六日。

### 1.2 筛选时点与答复时点

本期按咨询时间选出 `S`，不再要求答复日期也落在同一个区间。答复发生在区间外，不影响已入选子单按对应指标规则参与计算。

咨询时间仅在驳回到用户、用户重新发起时更新。当前节点累计时长可能继续随查询时间增长，旧审批流时长也可能按既有规则保留；不能把这些事实与“按哪天筛选”混为一谈。

## 2. 7项汇总指标总表

| 指标 | 统计公式或核心口径 | 分母/样本 | 单位 |
| --- | --- | --- | --- |
| 咨询总量 | `N` | 全部入选子单 | 单 |
| 日均咨询量 | `N ÷ D` | 筛选日期区间天数 | 单/天 |
| 有效咨询量 | 总量减三种完结状态子单数 | `E` | 单 |
| 总部按时答复率 | 按时答复子单数÷`N`×100% | 含按时、超时、未答复的全部入选子单 | % |
| 平均接单周期 | `A`中各子单的商经部答复时间至咨询时间的工作时长求平均 | 仅有指定答复时间的子单 | 天 |
| 技术部答复周期 | `E`中已有商技部累计小时之和÷`N_E`÷24 | 全部有效子单，不仅是已有时长的子单 | 天 |
| 对外答复周期 | `F`中完结时间至咨询时间的工作时长求平均 | 仅有完结时间的子单，不额外按状态排除 | 天 |

不同指标采用不同样本集合。不能用某一个指标的分母统一替代其他指标。

## 3. 咨询总量

咨询总量是统计周期及其他条件交集内的咨询子单总数，按咨询子单号去重，不按咨询单号合并。

待提交、待修改、已驳回也计入总量；待接单子单不因尚未接单而自动排除。每一条仍必须满足当前账号可见范围和查询条件。

例子：同一咨询单有3个入选子单，即计3单。三张状态不同，分别判断各指标的纳入条件。

## 4. 日均咨询量

```text
日均咨询量 = 咨询总量 / 筛选时间天数
```

分母来自所选日期区间，不是有单据发生的日期数，也不是审批耗时使用的工作日数。筛选区间的天数与“扣除非工作日的业务小时”分开处理。

例如10个自然日内有20张入选子单，日均为2单/天。审批时长排除休息日的规则，不会自动把日均指标的日期分母改成工作日。

本次没有额外统一日均咨询量的小数位数；不能把“周期天数保留一位”直接套给所有指标。

## 5. 有效咨询量

三种完结状态集合为：

```text
{ 已完结, 已完结无需非标选型, 已完结无选型方案 }
```

```text
有效咨询量 = 咨询子单总量 − 上述三种状态的咨询子单量
```

- 正常流程完成的「已完结」也扣除。
- 已驳回不属于上述三种状态，不能仅因名称有结束含义就将其新增进扣除集合。
- 待提交、待修改等未被排除的入选子单，仍可处于有效量集合。
- 同一咨询单下按子单状态独立判断。

例子：10张入选子单中，三种完结状态各1张，则总量10、有效量7。这个“有效”是本指标的状态集合定义，不代表已成功答复或已通过审批。

## 6. 总部与科室按时答复率

### 6.1 最终公式

```text
总部按时答复率 = 总部口径按时答复子单数 / 全部入选子单数 × 100%
科室按时答复率 = 该科室按时答复子单数 / 该科室范围全部入选子单数 × 100%
```

分母包含按时答复、超时答复和未答复子单，不只取已答复样本，不改为有效咨询量，也不按“是否已经到承诺时限”额外排除未答复子单。

例子：10单中7单按时、2单超时、1单未答复，则答复率70%。未答复进入分母但不进入按时分子，因此不能简单用“1减超时数量占总量比例”替代。

### 6.2 总部已答复事件

总部口径使用「商经部技术人员核对」节点的实际答复：

- 选择答复：取实际答复时间，判断时效。
- 选择驳回：不算已答复，不把驳回时间当结束时间；子单仍在分母中。
- 驳回后再次到该节点并实际答复：此时才以实际答复时间判断。

总部耗时：

```text
H(咨询时间, 商经部技术人员核对节点的实际答复时间)
```

原型中的销售公司申请时间，经用户确认为咨询时间。

科室指标使用对应科室的答复口径与该科室样本；本文没有将总部节点事件擅自重新命名为所有科室的唯一后端字段。

### 6.3 3个工作日的边界

- 按内部日历累计，每工作日24小时。
- 3个工作日对应累计72小时。
- `≤72小时` 算按时。
- `>72小时` 算超时。
- 72小时整按时；72小时零1秒超时。

1秒边界不能被展示舍入抹掉。判断是否超时应保留足以区分该边界的实际耗时，不应先将72小时零1秒舍入成72.00小时后再判按时。节点明细保留两位小时和时效判定边界是不同用途。

### 6.4 分母为0

暂显示半角连字符 `-`，允许前端后续调整最终展示。若分母大于0、按时分子为0，数学结果为0%，不能当作没有样本。

## 7. 平均接单周期

### 7.1 名称与实际时间跨度

保留指标名称「平均接单周期」，但按用户最后明确的公式，结束时间取「商经部技术人员答复时间」，不是接单时间。

```text
平均接单周期（天）
= Σ[H(咨询时间, 商经部技术人员答复时间)] / |A| / 24
```

仅对 `A` 中有该答复时间的子单求平均。没有该时间的子单，**分子、分母都不计入**，不以当前时间补算。

这里不按状态名称机械筛选；判断的是指定答复时间是否存在。不能沿用曾在讨论中出现但已被更正的“总子单数作分母”。

### 7.2 例子

两个参与样本的工作时长为24、72小时，另两个子单没有指定答复时间：

```text
平均接单周期 = (24 + 72) / 2 / 24 = 2.0天
```

不能除以全部4张子单。

另一个同一工作日例子：09:00咨询、10:00接单、18:00发生指定商经部答复，按最终公式其跨度是9小时。接单时间早于答复时间，不改变本指标已确认的结束事件。

### 7.3 无样本

`|A|=0` 时暂显示 `-`，允许前端调整最终展示。

## 8. 技术部答复周期

### 8.1 最终公式与样本

需求人员修订公式、用户进一步确认样本范围：

```text
技术部答复周期（天）
= 有效咨询子单中商技部技术人员答复累计时长总和（小时）
  / 有效咨询量 / 24
```

分子只汇总 `E` 中已产生的商技部技术人员答复时长。三种完结状态子单即使有历史时长，也不纳入本指标分子。

分母是全部有效咨询量 `N_E`，不能改为“有商技部时长的有效子单数”。有效子单没有该时长，不产生分子贡献，但仍属于有效量分母。

### 8.2 有时长不等于已完成答复

商技部累计时长来自既有审批明细第3项算法：

- 已完成审批段使用本节点审批时间减上一节点审批时间。
- 当前节点使用当前时间减上一节点审批时间。
- 驳回未完结后的再次审批也累计。
- 驳回完结后重新发起，多个相关审批流的对应进度时长仍累计。
- 新一轮未到该节点，不会清空旧流程已有时长。
- 累计后换算小时、四舍五入保留2位，排除非工作时间。

具体历史算法主维护于《技术咨询单审批统计：节点时长、驳回次数与跨审批流累计》。不能把“有时长”误改为“当前节点已成功答复结束”。

「商技部技术人员答复」与「商经部技术人员核对」是不同节点，不能混用时长字段。

### 8.3 例子

4张有效子单的商技部时长分别为48、24、24小时和无时长；另有已完结子单的120小时：

```text
技术部答复周期 = (48 + 24 + 24) / 4 / 24 = 1.0天
```

无时长有效子单仍在分母，已完结的120小时不进入分子。

### 8.4 零分母与零时长

- 有效咨询量为0：暂显示 `-`，前端可调整。
- 有效咨询量大于0，但商技部时长和为0：这是可计算的零值，不能仅因分子为0就强制显示 `-`。

## 9. 对外答复周期

需求人员的新说明为“咨询提交到单据完结的实际时长平均值”；用户明确以咨询时间为起点。

```text
对外答复周期（天）
= Σ[H(咨询时间, 完结时间)] / |F| / 24
```

### 9.1 参与样本

- 入选子单只要有完结时间就参与平均。
- 没有完结时间，分子、分母都不参与，不以当前时间继续计时。
- 不额外按状态排除，也不限定为有效咨询量集合。
- 已驳回若有完结时间则参与，若无则不参与；这不是对所有已驳回字段值的断言。

### 9.2 与审批总时长区分

```text
审批总时长：接单时间 → 完结时间
对外答复周期单单跨度：咨询时间 → 完结时间
```

二者都扣除非工作日，不能因为终点相同就复用同一个数值。

### 9.3 例子与无样本

两张有完结时间的子单分别有24、72个工作小时，另两张没有完结时间，则对外答复周期为2.0天，分母为2。

没有任何完结时间样本时暂显示 `-`，允许前端调整最终展示。

## 10. 环比

### 10.1 对比期

日期选择为单日时，对比前一日；选择区间时，对比本期之前紧邻的等长自然日区间。不是同比，也不是按工作日数量另选日期。

本期和上期采用一致的其他查询条件及对应指标口径。审批耗时排除非工作日，不改变对比期按自然日等长选择的规则。

### 10.2 三种不同的变化表达

| 指标类型 | 环比计算 | 例子 |
| --- | --- | --- |
| 咨询总量、日均咨询量、有效咨询量 | `(本期−上期)/上期×100%` | 上期10、本期20，增长100% |
| 总部按时答复率 | 百分点变化：本期百分比−上期百分比 | 50%到70%为+20个百分点，不能写成相对增长40% |
| 平均接单、技术部答复、对外答复周期 | 天数差：本期−上期 | 3.0天到2.0天为−1.0天 |

### 10.3 上期为0

需要以上期值作分母的增长百分比，上期为0时暂显示 `-`，前端可调整。

百分点差和天数差本来不除以上期值，不能仅因上期为0就套用该增长百分比空值规则。

## 11. 精度与无数据展示汇总

| 项目 | 规则 |
| --- | --- |
| 既有节点累计时长 | 多段相加后换算小时，四舍五入保留2位 |
| 平均接单、技术部答复、对外答复周期 | 按天展示，保留1位小数 |
| 维度/构成占比 | 保留2位小数，具体分母见图表知识文档 |
| 按时边界 | 保留可区分72小时整与多1秒的实际时长，不由显示舍入改变分类 |
| 总部/科室答复率无分母 | 暂 `-` |
| 三个周期无参与样本或相应分母为0 | 暂 `-` |
| 增长百分比的上期值为0 | 暂 `-` |

这些 `-` 是用户接受的暂定展示，允许前端调整最终表现，不应写成永久不变的外观约束。本文没有为咨询总量为0、合法0%或合法0天强制增加 `-` 规则。

## 12. 与原型及实施证据的关系

当前原型仍可能出现创建时间筛选、旧分母、技术部接单周期旧名称、旧第6/7项描述；应同步为本次已确认规则，而不是据此反复重开已解决口径。
