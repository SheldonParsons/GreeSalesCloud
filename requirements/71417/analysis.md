## 业务目标与本期变化

核心用户是收不到短信验证码、不能走双因子或手机验证码登录的保密区技术人员，通过格力互联进入业务系统。

本期在统一用户平台、CRM、订单管理端、订单客户端的登录页增加单点登录路径，同时保留账密和短信登录路径。核心用户描述不构成按钮可见范围的限制：不按“是否经销商”隐藏按钮，也不因内外网隐藏按钮。

## 四个平台的职责与主链路

依据图 2，主链路为：

```text
来源系统登录页 → 勾选隐私协议 → 点击“单点登录” → 格力互联认证/授权
→ 返回来源系统的授权处理链路
→ 当前业务系统使用本系统凭证领取内邮号
→ 交给统一用户管理平台，以“账号”匹配该内邮号
→ 对匹配账号执行仍适用的既有状态及访问资格检查
→ 返回来源系统中登录前访问的具体页面
```

图 2 明确了业务责任和结果方向，用户进一步明确成功后返回登录前访问的具体页面。回调地址、接口调用顺序、协议、会话创建方式均未提供，以上不作为技术实现设计。

| 来源系统 | 本期职责 | 成功返回范围 |
| --- | --- | --- |
| 统一用户平台 | 提供入口，作为来源系统处理授权并领取内邮号，同时承担账号匹配职责 | 统一用户平台 |
| CRM | 提供入口，使用本系统凭证领取内邮号，交给统一用户平台匹配，沿用适用的访问资格检查 | CRM |
| 订单管理端 | 提供入口，使用本系统凭证领取内邮号，交给统一用户平台匹配，沿用适用的访问资格检查 | 订单管理端 |
| 订单客户端 | 提供入口，使用本系统凭证领取内邮号，交给统一用户平台匹配，沿用适用的访问资格检查 | 订单客户端 |

以上按四个平台范围应用图 2 的通用规则，不推定四套凭证、四个独立后端或四套会话实现。账号匹配的统一责任不等于四个平台都先进入统一用户平台首页。格力互联是外部认证/授权依赖，不新增为本需求的第五个登录页改造对象。

## 已明确的业务规则

| 主题 | 图 2 规定 |
| --- | --- |
| 入口 | 四个平台登录页增加“单点登录”，保留账密、短信登录 |
| 单点登录专用路径 | 点击后进入格力互联，不经过业务登录页的滑块、短信验证码、双因子绑手机 |
| 原登录路径 | 账密、短信登录仍走现有滑块等校验；滑块用于防刷、不依赖手机，不因保密区使用场景整页移除 |
| 身份来源 | 通过后由当前业务系统使用本系统凭证领取公司认证返回的内邮号 |
| 匹配字段 | 统一用户管理平台的“账号”，不是“电子邮箱” |
| 匹配值 | 公司认证返回的内邮号；材料说明格力互联公司账号一定是内邮号，生产环境有内邮的用户创建时账号就是内邮号 |
| 唯一命中 | 账号具有唯一性，同一内邮最多命中一条；测试环境同一人存在多个测试号时，只进入账号等于内邮号的那条 |
| 未匹配 | 经销商等账号不是内邮号时可能无法匹配；无账号命中则提示“账号未绑定”，不自动建号 |
| 匹配后仍检查 | 禁用、离职、不允许登录本系统、不具备角色、渠道公司停用等，沿用现有提示 |
| 单点登录不套用 | 账号与密码是否匹配、密码到期强制改密、首次登录强制改密、弱密码强制改密、因连续输错密码导致的账号锁定、双因子绑手机、登录页滑块 |
| 按钮可见性 | 不因是否经销商、内网或外网而隐藏 |
| 回到来源系统 | 从哪个系统点击，授权结束后回到哪个系统 |

“账号禁用”和“连续输错密码导致的账号锁定”是不同规则：前者沿用既有检查，后者不套用于单点登录。单点登录免除的是指定登录路径的校验，不免除账号状态和访问权限检查。

## 异常分支

| 发生位置或条件 | 已明确处理 |
| --- | --- |
| 格力互联侧失败 | 由格力互联自己的页面处理；材料注明统一用户管理平台不管 |
| 授权已回，但未领到内邮等 | “单点登录未完成，请重试。” |
| 已获得内邮号，但对不上任何“账号” | “账号未绑定”；不自动创建账号 |
| 命中账号，但禁用、离职、无系统登录资格、无角色或渠道公司停用等 | 沿用现有提示，不修改 |

不能把“未领到内邮”与“已领到内邮但无匹配账号”合为同一个错误。取消授权、回调失效、匹配服务不可用等具体异常如何归入上述分支，材料尚未逐项说明。

## 用户补充确认

2026-10-20，针对首轮三个问题，用户分别确认：

| 问题 | 用户确认 | 对验收的影响 |
| --- | --- | --- |
| 平台间登录关系 | “登录一个平台和其他平台无关，还是要登录，是单独的” | 四个平台分别完成登录；不能以 A 已登录为由跳过 B 的登录流程。不据此推定后端会话存储结构或格力互联侧是否再次展示授权页面 |
| 成功落地页面 | “登录前访问的具体页面” | 需在授权、回跳和账号校验后保留来源系统及原目标页面，不能统一改为首页 |
| 隐私协议 | “是”单点登录的前置条件 | 未勾选时不能发起单点登录；勾选后才进入授权流程。图 1 为当前已见 UI，其余平台协议控件形态尚未查看 |

不将跨平台自动登录或退出/过期联动新增为本期要求。用户本轮明确的是登录独立，尚未逐项描述各平台自身的退出、过期行为，相关回归以可核对的既有规则为准。

## 场景结构与回归影响

以下为分析维度，已用于编写正式 Mind 用例初稿；这些条目本身不是执行结果：

- 四个平台分别验证入口、发起授权、使用来源系统身份领取内邮、匹配账号、返回来源系统的完整路径，不能用一个平台的成功代替其余三个。
- 按钮可见性与登录资格分别验证：经销商或外网仍可见入口，不等于一定能匹配账号或具备系统访问权。
- 身份匹配覆盖账号命中、仅电子邮箱相同而账号不同、同人多个测试号、无匹配账号；其中仅电子邮箱相同不能作为账号匹配成功的依据。
- 对单点登录不适用的密码校验和锁定，需与仍适用的禁用、离职、系统访问资格等分别核对。
- 区分格力互联失败、授权返回后未取得内邮、取得内邮但未匹配、匹配后访问受限，核对各自结果。
- 回归原账密和短信路径、各自既有校验及滑块，避免新增单点登录影响原路径。
- A 平台登录后，其他平台仍需各自登录；四个平台的来源与回跳目标不能混淆。
- 从具体业务页面进入登录流程时，授权和账号校验成功后返回该页面；不能仅核对“回到了同一个系统”。
- 隐私协议未勾选与已勾选分别覆盖；未勾选不得发起单点登录，控件禁用还是点击后提示及具体文案尚无依据。
