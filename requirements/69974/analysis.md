# 69974 首轮需求理解与范围分析

2026-09-21；状态：已补三版历史需求并更新差异，关键问题待澄清，尚未进入正式用例或执行阶段。先阅读 [业务基线](baseline.md)，材料版本和证据索引见 [sources/README.md](sources/README.md)。

## 1. 这件事的业务目标

整体二期面向 MTO 订单从销售审核到生产完工的履约过程：看技术 / 生产进度，发现预警与超期，针对变更组织评审，记录日期变化和审批过程（S2 §2–§4）。

69974 是其中销售审核页面的落地任务：区分审核前后的列表数据，已处理记录按实际排产单元展示，让销售在合适的生产阶段发起或处理订单评审。不能把整个履约监控二期、整个 0930 需求池都归入 69974。

S1 共列 7 项：销售审核 Tab、非标定制数据对象、生产计划、详情状态交互、履约监控 Tab 数据取值、履约监控整体概述、审批页说明。本任务先聚焦第一项；其他项目作为上下游关联，具体交付边界待确认。

## 3. 数据对象是本期最重要的变化

| 区域 | 一条记录代表什么 | 关键规则 |
| --- | --- | --- |
| 待处理 | 需求计划明细行 | 沿用现有数据及交互 |
| 已处理—已分单无需排产 | 需求计划明细行 | 排产相关字段为空，交货日期明确显示 `--`；操作仅查看 |
| 已处理—已分单需排产 | 排产基地说明 | 按排产单元承接状态、日期和后续评审；可涉及套机、单机及原文“单机下的套机数据” |

S3 菜单权限段笼统将已处理归为排产基地说明，后文明确包含无需排产的明细行例外，整理时保留该例外。套机展开、行数、关联展示结构尚未给出，不能自行定行展开规则。

一个需求计划明细可产生多个排产基地说明；一个排产基地说明最多对应一个后创建的生产计划；每个基地说明对应自己的履约监控载体（S2 §5.1、§6.4）。因此，按订单号合并或只展示原始明细，可能丢失独立的生产进度和评审对象——这是基于对象关系的影响分析，非已观察缺陷。

## 4. 已处理字段来源

S3 行 63–81 定义 19 个业务字段：

| 来源 / 含义 | 字段 |
| --- | --- |
| 订单、订单行及客户 | 订单编号、商品型号、商品编码、订单数量、接单日期（订单审批通过日期）、发货日期（计划发货日期）、客户名称、备注 |
| 需求计划明细及项目快照 | 项目名称、审核人、审核时间、订单等级 |
| 排产相关 | 生产用编码、排产状态、生产批次、生产数量、生产类型、交货日期、生产基地 |

- 项目名称来自明细绑定的项目快照，无则 `--`；客户名称无则空；未审核的审核人 / 时间显示 `--`。
- 发货日期、交货日期、整机生产完工日期为不同业务值，不能混用。交货日期由排产基地说明的排产情况表 `delivery_time` 提供；整体 PRD 修订记录将发货日期标为订单明细表 `delivery_date`。
- 页面字段表多处写“排产基地分布”，整体 PRD §6.4 和附录却明确“排产基地说明”对应排产情况表，并非基地需求分布表。业务对象已在整体方案澄清，但具体字段映射仍需对齐，不能直接采用同名近似表。
- 已处理列表“排产状态”字段自身枚举需确认：排产基地说明四态与生产计划五态分别存在；按钮取生产计划状态已明确，不等于显示列也必然取五态。

## 5. 状态与操作

S3 V1.2 明确已处理按钮按关联生产计划明细状态控制；旧的需求计划明细行状态表仍保留，按修订记录理解其对象层级。

| 条件 | 可见操作 |
| --- | --- |
| 无需排产 | 查看 |
| 需排产，但不存在关联生产计划 | 仅查看 |
| 生产计划待下发 / 已排产 / 生产中 | 查看；满足附加条件后可修订、发起订单评审、审批评审单 |
| 生产计划已完工 | 仅查看 |
| 生产计划已取消 | 规格列仅查看，但为预留状态、当前无业务场景 |

附加条件：修订要求开发状态不为“无需处理”，二次确认发起技术修订；发起订单评审要求当前无审批中的评审单；审批入口要求有关联进行中评审且当前用户为审批人。页面将评审单“评审中”和“审批中”混写，整体方案区分监控器评审状态与评审单审批状态，需落实到对应对象。

两套排产状态不能混为一套：

- 排产基地说明：待指派 → 待排产 → 已排产 → 已完成。已存在生产计划且排产时间为空，基地说明仍为待排产；其状态还依赖排产时间与当前日期、完成数量等。
- 生产计划：待下发 → 已排产 → 生产中 → 已完工；另有预留已取消。生产节点监控完成以生产计划“已完工”为锚点。

需求计划明细“已关闭”明确为后续拓展，本期不涉及。

## 6. 销售发起订单评审

入口为已处理行的“发起订单评审”，打开抽屉，选择重大变更 / 客户加急（S3 行 83–108）。

- 变更原因必填，500 字以内。
- 是否需要暂停生产：是 / 否，默认否；整体方案不做自动停线，不能将选择“是”理解为系统自动暂停产线。
- 交货日期（变更后）必须晚于当前日期；是否必填未明确。页面写默认取关联需求计划明细的交货日期，与列表改为基地说明日期存在口径待确认。
- 发起方为销售；没有有效审批流时提示“未找到审批流，请联系系统管理员。”
- 同一排产基地说明同一时刻只能有一个进行中的评审；创建评审单、固化节点时间快照、写管控日志，监控器评审状态更新为评审中。
- 标准商品直接进入生产部审批；非标商品技术、采购会签后，由生产部审批；销售发起方不参与会签。会签 / 审批在商用排产系统闭环，HCH 承接结果同步。
- 通过后更新相关日期、评审结果和监控器评审状态，写管控及字段变更日志，回推 HCH；驳回记录对应状态和管控日志，整体方案另要求回推审批结果。
- 过程日期由相关审批人手工逐项调整，不能根据销售改交货日期自动反推。过程日期允许今天（≥ 今日），销售的变更后交货日期要求晚于今天，两者不是同一字段的冲突。
- 评审快照用于查看和追溯，不作为后续日期运算的业务判断依据；历史评审可多次，当前只关联最新评审。

“审批订单评审”点击后打开新标签页展示评审详情（S3 行 131–135）。详情内完整字段和审批交互本轮材料不足。

## 7. 权限与上下游联动

数据权限与管理端订单列表一致：**（部门监管 ∪ 渠道监管）∩ 产品线**；部门监管包含下级组织，产品线按账号组织配置，两个 Tab 各自配置菜单权限（S3 行 13–28）。这些是目标要求，未实测旧版实现。

销售审核通过是二期履约监控启动点：T0 为审核通过日；技术与采购日期按咨询单周期赋值，整机生产完工日期统一为 T0 + 订单行供货期（S2 §8.1）。非标且带咨询单才有技术 / 采购对应日期，其中长线采购不限于大机组；压缩机、壳管、变频器采购齐套日期仅大机组有值。需技术答复时生产节点在答复生产文件号后启动，否则在审核通过时启动。

整体方案还涉及每天 SLA 扫描、预警求助自动发起、超期评审、字段日志、BI 回流等。它们是本页面联动与后续回归关注点，不据此全列为 69974 新建功能。采购节点不参与 SLA；技术修订流程一期已有；自动停线、明细已关闭、生产计划已取消的实际业务不在本期建设。
