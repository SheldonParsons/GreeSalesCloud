# 68701 首版用例的公共准备与数据绑定

适用文件：`V7.32版本_金叶轮菜单管理与数据字典_lb_20261030.amind`。本文件是同目录导图中准备条件的定位入口，不是第二份用例集，也不是执行记录。

当前版本V7.32、发版日期20261030。所有场景均未执行；实际业务环境、部署版本、测试账号、若干控件标签及数据准备方式尚未核对。下列名称和变量均为拟定测试输入/输出绑定，不是已存在的业务事实。未满足某条前置时，该场景不得判为通过。

## P0 登录与定位

1. 执行前取得本次测试授权，记录金叶轮实际环境URL、部署版本或时间、账号及权限范围。不能用本地原型、摹客或订单系统环境替代金叶轮业务环境。
2. 准备独立浏览器会话：A为具备本场景菜单/操作权限的管理员；B为通过已核对角色获得目标菜单的普通验证账号，不使用全菜单或超级管理员旁路；N为未获目标菜单权限的对照账号；C为权限变化测试用户；U为无管理模块菜单/操作权限的用户。每次登录或切换后核对界面实际账号，与准备记录一致。不得因标签页仍打开就假定身份正确，不能用A的菜单管理树代替B本人导航验证。
3. 使用已确认登录入口完成登录。菜单场景进入【平台设置 / 菜单管理】，字典场景进入【平台设置 / 数据字典】；记录实际页面地址，用于无权限直达验证。目标平台必须为金叶轮。页面的赛届展示不作为菜单/字典按赛届隔离的证据。
4. 执行前核对组件文字和可操作性。S10新增菜单截图已确认【类型】为菜单/子菜单/按钮/信息四选一，字段为【名称】【编码】【图标】【权限】【排序】【备注】及【启用】复选框，操作为【取消】【保存】和右上角【×】；新增分支已按这些用词修订。其他菜单入口来自旧原型，其他类型或编辑弹窗不能仅靠这张新增截图推定控件。字典列表的【新增字典】【新增字典项】【编辑】【删除】【查询】【重置】【↑】【↓】来自原图；字典表单保存按钮实际名称仍待核对。截图核对不等于当前业务环境已验证；不要猜控件坐标。
5. 每场景单独准备起始状态，记录Mind场景节点ID、实际操作账号ID、开始/结束时间和必要的对象快照。创建后记录实际对象ID、编码/值及父级ID；后续凭这些标识定位，不查“最新一条”。导图没有把示例ID当成真实ID，也没有预填通过结果。
6. 公共准备输出：`environmentUrl`、`deploymentVersion`、`accountIds`、`menuPageUrl`、`dictionaryPageUrl`、实际控件映射、`caseStartTime`及本场景实际对象映射。原始凭据和会话只在本机使用，不写入本文件、导图或Git。
7. 同一场景内跨角色连续编号，并使用隔离会话交接实际ID；不同场景重新从1编号。仅执行场景目标所需动作，不顺手审批业务、删除其他数据或扩展到赛事模块。

没有真实环境或账号时可以评审用例，但不能声称可无人值守执行。测试时未获取实际控件、引用数据或日志入口的检查项，应记录为准备不足/阻塞。

## P1 菜单基础数据

使用获准的独立测试数据，名称和编码附本轮短后缀K；K可取执行批次的数字时间串并写入本机运行记录。以下是数据模板，每条场景只准备其明确列出的节点；例如场景指定两个子级时不额外加入第三项。不得沿用上一场景修改后的状态。

| 别名 | 计划结构与用途 | 必须记录的输出 |
| --- | --- | --- |
| R_A、R_B | 两个名称、编码可区分的第一层菜单，例如“菜单根A_K”“菜单根B_K” | 实际ID、名称、编码、全部字段、原同级次序 |
| C_A1、C_A2、C_A3 | 按场景需要准备在R_A下的第二层节点 | 实际ID、父级R_A的ID、字段及原顺序 |
| C_B1 | R_B下第二层节点，跨父级拖动的对照 | 实际ID、父级R_B的ID及原顺序 |
| R_EDIT | 可修改的独占根菜单 | 编辑前完整字段、实际ID；本次变更值 |
| R_DELETE | 删除场景独占根菜单，含两条明确记录ID的子级 | 根和完整子级ID集合、角色关联集合及原字段 |
| R_KEEP | 删除/授权验证时应保留的对照菜单 | 实际ID、所属角色及有效访问结果 |

准备时使用经核实的现有菜单维护入口或由开发提供的隔离测试数据，不直接修改未知数据库。菜单最多两层。根菜单必须按已有要求完成图标等校验；字段完整性按P2落实。来源中的“允许子级”类别不能突破用户确认的两层上限。

## P3 菜单类别限制数据

R_INFO表示已核实为“信息”的节点；R_BUTTON_INLINE表示“非新开按钮”；R_BUTTON_PAGE表示“新开页面按钮”。S10明确类型枚举为菜单、子菜单、按钮、信息；“新开/非新开”是S8中的按钮行为区分，不另造第五种类型。切换后三种类型的具体字段、打开方式控件及这些数据的准备方式仍未核对。

为单独验证类别限制，相关场景要求目标位于第一层，避免因已经位于第二层而把深度限制误判为类别限制。执行前由可追溯来源准备并记录类型、打开方式、层级和真实ID；若无法构造该前置，保留该场景未执行并回到分析记录补证，不将普通二级节点冒充类别数据。

| 别名 | 必需条件 |
| --- | --- |
| B_VALID | 有效签名及完整结构，含两组可新增的根/子级；目标上下文中这些待新增节点不存在，且不会超过两层 |
| B_MIX | 同时包含当前已存在的E和待新增的N；E的身份匹配依据已核对，N父级已满足；用于区分已有与新增，不覆盖已有配置 |

## P-LEN 边界字符串

边界值在实际执行记录中保留完整原始文本并核对字符数。中文长度使用普通单个汉字，ASCII长度使用普通字母/数字，不用emoji或组合字符混入尚未确认的计数规则。

- 菜单名称30/31字符、备注200/201字符：使用单个汉字重复至指定长度，末尾可用另一普通汉字区分数据，长度保持不变。
- 菜单标识100/101、权限标识100/101、URL200/201：先取得现有格式规则认可的基线，填充至指定长度；超限组仅改变长度，不混入格式错误。当前具体格式未完整提供，执行前先核对，不以猜测的合法字符串判缺陷。
- 字典类型名和项名50/51、备注500/501：普通汉字重复至指定长度。类型名全局、项名本类型内保证未占用。
- 字典类型编码100/101：使用字母A开头的纯字母/数字/下划线序列至指定长度；字典项值100/101可使用普通ASCII序列。需要唯一时在总长度内换尾部字符并记录，不额外拼接导致长度变化。
- 1字符和空值边界按导图具体输入执行。类型名称三个空格经去首尾空格后应为空；不把该去空格规则自动推广到未明示的其他字段。
- 字典不允许通过前端静默截断后保存。菜单超长场景需区分控件限制和服务端拒绝，不能用输入框maxlength观察代替接口校验结论。

## P-ROLE、P-BIZ 菜单角色关系与业务对象

P-ROLE：删除场景使用下方P-BIND的真实关联记录，B仅通过指定测试角色取得目标菜单权限，避免其他角色授权掩盖删除效果；保留R_KEEP的有效授权。执行删除后用角色ID、账号ID及菜单ID集合核对清除范围，不顺手修改其他账号角色。

P-BIZ：为菜单删除“不删除业务对象”的检查提供获准的测试业务对象，记录其真实ID、只读访问路径、关键内容及状态快照。此处只核对对象保留，不开展赛事审批、投票等业务流程。没有可用对象或只读入口时，该检查点记录准备缺口，不用菜单消失推断业务对象保留。

## P-BIND 菜单→角色→账号的准备与交接

依据S11用户确认：菜单绑定到角色，角色绑定到账号；调整菜单后必须使用账号验证实际效果。角色暂作为既有测试关联，不在本需求展开角色新增、编辑、权限合并或账号生命周期测试。

输入：本场景实际菜单ID集合`menuIds`、既有有效测试角色`roleId`、普通验证账号`accountIdB`，必要时还有对照账号`accountIdN`。R_AUTH只是角色参数别名，不是系统中已存在的真实角色名。

1. 配置负责人按已核对的权限配置入口，用真实菜单ID定位本场景菜单，将其与实际R_AUTH角色关联；涉及根和子级时明确确认所需各节点，不默认“根已授权就自动授权所有新子级”。
2. 核对B账号与R_AUTH角色的关联。若已存在则只回读，不反复修改；新增/导入得到新菜单ID后，需要由配置负责人完成对应菜单关联，再交接给B验证。
3. 分别回读菜单与角色、角色与账号两段关系，记录实际ID、可读名称、当前有效状态和核对时间。不能用两个同名对象或一次保存提示代替真实关联核对。
4. 向账号验证步骤交付`{menuIds, roleId, accountIdB, expectedMenuNames, parentIds, order, targetPages}`；涉及N时补充它未获这些菜单或同一受限目标权限的依据。
5. 对修改名称/图标/路径、排序、取消、失败、删除等场景，在动作前完成绑定；动作后不偷偷重新分配角色或重建菜单来修复结果，否则会掩盖配置生效问题。新增和导入场景则在取得新菜单ID后显式完成绑定步骤。

当前未提供角色/账号绑定页面的真实入口与组件。执行准备阶段可由熟悉平台的授权配置负责人完成上述关联并提供回读记录；本轮不臆造角色设置按钮，也不把这份准备描述当作已采样的自动操作脚本。未得到真实关系时，账号验证步骤记录准备缺口，不能省略绑定核对直接使用管理员账号验证。

## P-ACCOUNT 账号侧菜单验证

1. 为A、B、N准备隔离浏览器会话；每次操作前核对当前账号标识。B是实际通过R_AUTH获得菜单的普通账号，不能具有会绕过该链路的全菜单权限。N不能通过其他角色或另一菜单取得同一受限目标权限。
2. 记录B本人导航中的目标菜单名称、图标（该位置实际展示图标时）、层级、同级相对次序和可跳转目标。不要在【菜单管理】配置树里代替这一项检查。账号侧导航区域、登录入口及页面标识当前待真实环境核对。
3. 配置变更后在B当前会话重新加载导航，并在场景要求时退出重新登录复核。刷新和重新登录用于取得当前有效菜单，不额外规定秒级刷新时限，也不写成已经验证的缓存机制。
4. 可跳转菜单必须使用已完成且属于本次获准测试范围的目标页，记录实际地址及可识别页面名称/业务标识。点击后核对实际落点，不只判断“打开了一个页面”。不在目标页继续审批、提交作品或执行其他业务写入。
5. 负向直达验证仅使用已确认受该菜单有效授权保护的目标，不能拿本来公开的页面证明权限失效。保存删除前/停用前的实际路径，在对应账号隔离会话核对拒绝结果；隐藏导航不替代访问控制检查。

| 别名 | 用途与输出 |
| --- | --- |
| R_AUTH | 已准备的测试角色；记录真实角色ID，关联菜单ID集合及B账号ID |
| B | 已绑定普通账号；记录真实账号ID、实际显示身份及隔离会话，不记录凭据 |
| N | 未关联目标角色且没有其他等效授权的对照账号 |
| M_ICON | 已绑定且在账号侧实际展示图标的菜单，记录原图标/名称和菜单ID |
| M_ROUTE | 支持编辑跳转配置的已绑定叶子菜单；记录原路径与适用字段入口 |
| PAGE_A、PAGE_B、PAGE_NEW | 已完成且获准访问的不同目标页面，记录真实地址和页面标识；不是虚构页面名 |
| M_STATE | 启停场景的独占叶子菜单，记录状态、有效关联和目标页；不从叶子规则推定父级停用如何影响子级 |
| M_PRIVATE | 用于B/N权限对照的受限菜单和对应目标 |
| R_KEEP | 应保留可用的对照菜单及目标，防止只检查目标消失而漏掉误伤 |

菜单启用恢复场景需先确认停用记录仍有相应绑定，不能假定停用必然保留或删除关系。图标场景也要求账号侧确实存在图标呈现位置，不能臆造位置或样式。

2026-10-21已检索本仓库UI能力目录，未定位到金叶轮对应可复用契约；现有商用订单QA能力不替代本平台页面。当前未进行账号登录、绑定或页面采样；执行前按`context/page-sampling.md`在授权环境落实。

## P-REF、P-HISTORY 字典引用数据

由开发/业务方提供可追溯的隔离引用数据和只读入口，不凭名称“猜一张单”。输出项ID/稳定值、类型ID、引用对象真实ID、引用字段位置、读取路径及当前业务状态。

- I_REF与REF_ITEM：非默认且已被引用的字典项，适用于更名保持稳定引用及禁止删除。
- D_REF与REF_TYPE：没有字典项但类型本身被引用的数据，用于独立验证类型引用限制。
- I_ACTIVE与REF_ACTIVE：非默认、存在在用引用，且已由现行规则确认直接停用会使该业务失效；用于停用拦截。不能把所有历史引用等同于在用失效。
- I_HISTORY与HISTORY_ID：非默认、无会受停用影响的在用业务，但有历史显示记录；提供原显示内容和历史对象ID，用于停用不影响历史显示。

上述引用模型/入口当前尚未提供。需要时先补齐准确数据，不能把未取得引用数据的场景标成通过，也不为准备这些数据自动开展本需求之外的业务写入。

## P-FAIL 确定失败的保存条件

仅在授权测试环境使用可控制且已核实的失败条件，针对本场景对象让服务在持久化前明确拒绝本次写入。记录失败设置、实际请求对象及前后有效记录的只读核对方式。

不能简单断网后就断言服务端没写入；如果请求结果未知，应先按对象ID核对有效状态，不以新请求重复重放。当前没有故障注入入口，相关场景属于待执行准备，不实施生产故障或未经授权的环境修改。

## P-SORT 排序保存方式

执行前核对当前页面是拖放/箭头后自动保存还是另有保存动作，记录实际控件与保存反馈；导图写“完成保存”时引用该已核对方式。业务预期是刷新后次序保留，不能仅看本地视觉位移。

菜单只在同一父级下排序且不能改变层级；字典项只在同类型内拖动或上下移动，不能改值及引用。保存动作的具体交互属于当前页面待核对信息，不再次把“是否支持字典拖动”当成需求疑问。

## P-LOG 操作日志核对

执行前取得获准的日志查看页面或只读查询入口及账号权限，记录字段对应关系。当前未取得实际日志界面，不能编造日志菜单名。

操作前记录对象ID或待新增唯一编码、操作者实际账号ID、开始时间及关键旧值；操作完成记录对象实际ID、结束时间和新值。用对象ID、操作类型、账号及时间范围定位对应日志，核对实际人、时间及前后值。新增前值应体现此前不存在，删除后值应体现删除；默认切换核对旧/新默认，排序核对原/新顺序。日志展示格式不预设，不用“最近一条”代替定位。

没有日志读取权限或入口时，只能将日志检查标为阻塞，不能以保存成功提示代替日志证据。

## P-CLIP 剪贴板受限条件

在隔离测试浏览器中准备已获准且可恢复的剪贴板不可用条件，不更改用户日常浏览器权限。记录限制方式，核对复制弹框仍有完整内容；手工取得的内容只粘贴至本平台批量新增预览，不自动提交业务新增。

## P-ROUTE 后续页面接入条件

先记录已经提前保存的M_FUTURE菜单实际ID、配置路径、名称及字段。待开发负责人在同一获准测试环境完成对应页面并提供目标页面名称/标识及可访问依据后，再执行“原菜单自动接上”场景。测试人员不因该场景自动部署或发布功能；没有已完成目标页面时该场景保留未执行/阻塞。验证后仍是原菜单配置，不依靠重建菜单或手工重新绑定使结果成立。

## 执行结束的数据边界

用例达到自身目标即结束，保留本次实际标识用于追溯。创建型场景不会顺手删记录；删除型场景只处理其明确独占测试对象。批次统一清理需另按测试授权和数据归属处理，不触及共享或未知业务数据。
