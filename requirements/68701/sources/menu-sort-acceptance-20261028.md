# 菜单排序非法输入的验收补充（2026-10-28）

来源：本需求业务协调会话中，用户对执行中发现的菜单排序自动纠正行为作出直接确认。

原问题：菜单排序输入-1、10000、1.5等非法值时，是否允许页面自动改成合法整数后保存。原材料明确0—9999的整数范围，未说明自动纠正方式；已有用例把它收紧为必须拒绝且不得新增。

用户原话：

> 不管是自动修正还是提示，只要保证保存后不是非法值即可

## 生效规则

- 菜单排序最终持久化值必须为0—9999的整数。
- 允许自动修正为合法整数后保存；也允许提示用户修正或拦截非法输入。不得仅因自动纠正就判失败，不附加“必须纠正到最近边界”的规则。
- 自动修正后实际保存的合法值必须回查确认；界面显示或成功提示不能替代持久化结果。
- 此补充仅处理原输入非法的情况，不放宽合法输入的保持要求。输入合法上限9999却被改成1000的已证实问题仍保留。
- 不更改数据字典关于“不通过前端截断保存”的明确要求，也不更改菜单其他字段长度规则。

## 用例与执行影响

适用现行场景：

- `mcp-node-mvhu73w6-44`：排序填写-1。
- `mcp-node-mvhu73w7-6`：排序填写10000。
- `mcp-node-mvhu73w7-15`：排序填写1.5。

由正式Mind唯一写入者原位修订相关预期，保留节点ID及其他元数据，并按已有实际保存/回读证据复核结果。负数被修正为0且回查仍为0，不应因自动纠正被记为BUG；历史结论调整需说明依据。尚未取得持久化证据的场景不能直接标通过。
