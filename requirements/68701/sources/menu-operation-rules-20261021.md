# S8：菜单操作与处理规则补充

来源：用户于2026-10-21在本需求会话转交需求人员的补充截图，并要求查看。未提供文档版本号。

原件：[操作与处理规则](menu-operation-rules-20261021.png)。原图已完整读取并原样归档，校验值见 [checksums.md](checksums.md)。本记录只转写补充材料，不表示业务测试已执行，也不表示旧本地原型已更新。

## 原图逐项转写

| 操作 | 处理逻辑 | 结果与异常 |
| --- | --- | --- |
| 新增菜单 | 根级新增；根菜单上传图标 | 名称、编码、图标等校验成功才保存 |
| 新增子级 | 从目标节点操作，父级固定为该节点 | 菜单、子菜单及新开页面按钮允许子级；信息及非新开按钮不允许子级 |
| 编辑 | 回显目标节点全部字段 | 不再打开目录中的首个菜单项；类型不可改，其他可见字段保存生效 |
| 删除 | 确认后删除目标及全部子级 | 不是仅提示暂不可删除；角色菜单关系同步清除，不删除业务对象 |
| 复制/复制全部 | 输出含完整节点、子级及校验签名的GISMENU.1.编码内容 | 不立即创建副本；剪贴板不可用时可手工复制弹框内容 |
| 批量新增 | 粘贴复制内容、校验完整性、预览已有与新增节点、选择新增节点 | 已存在节点不能重复创建；缺父级、编码冲突、结构或签名无效时阻止 |
| 拖动排序 | 只允许同一父级下改变顺序 | 保存同级序号；跨层拖放不改变结构 |

## 对现有材料的解释边界

- 复制与批量新增形成“输出编码内容 → 粘贴校验 → 预览并选择 → 新增”的关系；复制动作本身不创建副本。`GISMENU.1.` 为原图文字，不推定其具体编码、签名算法或安全属性。
- 菜单删除明确处理目标、全部子级及角色菜单关系，保留业务对象。该规则只用于菜单，不能覆盖数据字典已明确的引用删除限制。
- 本图同时说明复制与复制全部，作为菜单复制功能的补充规则保留；复制全部的具体应用/节点集合边界未展开。
- 本图给出允许子级的父节点类别。后续用户在S9明确菜单最多两层，第二层不再新增子级；完整类型枚举、各类型完整字段以及图标文件约束尚未完整给出。
- 缺父级、编码冲突、结构或签名无效会阻止操作已明确；后续用户在S9进一步确认一条不合法则整批不保存，不允许部分新增。
- 新增菜单、编辑和排序规则补充了产品要求，不能据此声称2026-10-20读取的原型代码已经实现。
- 字典拖动已由S4/S7原文明确，不需由本菜单补充图再回答。菜单目标页面是否完成不作为保存前提，用户后续明确可以先保存、页面做好后自动接上，其他已有校验仍适用。后续确认与纠正见 [S9](clarifications-20261021.md)，当前问题统一在 [analysis.md](../analysis.md) 维护。
