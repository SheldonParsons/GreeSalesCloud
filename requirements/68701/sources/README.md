## S1：业务背景转写

“金叶轮”暖通空调设计大赛每两年举办一届。赛事需协同参赛设计师、格力初审人员、专家、主审专家、平台管理员和组委会，完成赛事发布、作品申报、格力初审、专家预审、作品分组、专家评审、小组评审、两轮全体专家投票、奖项确认、打印签字和结果归档。平台用于统一承载上述业务过程，解决线下表格、文件和现场沟通分散造成的进度不透明、权限边界不清、结果合并成本高及历史数据难追溯问题。

以第7届赛事现有数据为例，共收集240份作品，其中工程设计类233份、工程应用类7份。两轮投票和最终奖项执行当前已确认规则：第一轮默认计划入围126份，按符合资格的工程设计类与工程应用类统一候选池计票，边界同票作品全部纳入，实际数量可超过126份；第二轮按金奖1分、银奖2分、铜奖3分、优秀奖5分进行逐项投票，金银铜优名额后按固定新锐奖名额授奖，超过全部奖项名额的实际候选不自动获奖。

上述数字和规则是原图中的赛事背景，不能据此生成本次菜单或数据字典的验收要求。

## S2：现状与核心痛点转写

| 业务环节 | 主要问题 | 平台解决方向 |
| --- | --- | --- |
| 赛事信息发布 | 赛事品牌、核心价值与官方信息入口分散 | 增加“赛事中心”落地页，首屏集中展示赛事品牌和三项核心价值，并承载官方信息与登录入口 |
| 作品申报 | 申报类型与作品字段处于同一页面层级，容易混淆入口判断与实际作品录入；参赛单位地址、项目地址和协助申报单位口径不清 | 将申报类型选择前置为独立入口页，确认后再进入对应表单；地址分开维护；协助申报单位使用导入单位数据单选且非必填 |
| 格力初审 | 审核范围和作品业务特征依赖人工辨识 | 支持按地址等属性筛选，并使用平台管理员维护的启用标签完成初审打标 |
| 专家预审 | 线下签字结果缺少系统闭环 | 系统生成当届预审意见书，线下统一签字后由平台管理员上传一份有效文件 |
| 作品分组 | 分组依赖线下表格，规则无法沉淀、调整难追溯 | 在作品分组页自动平均分组，随后组内专家指派；分组规则仅预留外挂入口 |
| 专家评审 | 量化评分口径与本次业务评审结论不一致 | 仅由被分配专家对本人待评作品标记“优/良/中/差”并填写“作品亮点” |
| 小组评审 | 小组讨论结果与组内作品可见范围缺少统一控制 | 现场阶段开放同组互看和共同讨论，由组长确认并提交排序、推优项目和拟推荐奖项 |
| 全体专家投票 | 作品数量多，跨组浏览和组内结果参考不直观 | 两轮均按评委组分区连续展示，并呈现组内评优排序；不使用组页签切换，不按全局序号混排 |
| 奖项确认与签字 | 最终评语和线下签字对象不明确 | 主审专家逐条维护金银铜奖最终评语；金银铜奖结果统一打印并完成线下专家签字 |
| 历史赛事 | 后续操作可能覆盖历史数据 | 所有业务数据按赛届隔离；已结束、已归档赛届仅允许查看、打印和导出 |

这些方案是否约束平台通用菜单或字典管理，尚无直接材料依据，应在详细模块需求中核对，不将赛届隔离等规则自动推广到系统配置数据。
