# 机型非标点：批量导入与重复拦截

主维护项目：商用订单管理系统-管理端。适用范围：机型非标点清单上传、逐行校验、导入结果及新增审批。依据为已读取的批量导入原型、两版历史用例及用户最新确认；本条描述业务要求，不代表已执行系统测试。

配置状态和物料的通用录入规则主维护于现有知识条目“机型非标点：已配置时增减物料允许为空”（正文已扩充为“添加、编辑与配置状态规则”）。本条说明它们在导入中的适用方式，不恢复旧的非空限制。

## 1. 导入入口、模板及上限

入口为商品中心→非标点管理→机型非标点管理→批量导入。用户下载模板，填写机型非标点清单后上传指定格式的Excel文件。

**单次上传最多100条，以生产用编码＋非标点作为一条记录。** 用户已咨询产品并确认100条；历史提示的1000条及曾经按1000条定稿的记录均已撤销，不作为现行上限。

必填字段是生产用编码、非标点名称、配置状态。商品型号、商品编码非必填；即使填写了，也必须与生产用编码对应，不能填写任意不匹配值。最终用生产用编码反查的商品型号和商品编码进行绑定。

配置状态默认空，必须选择已配置或未配置。增加物料、减少物料根据下述规则校验，已配置时可以同时为空。

## 2. 三步导入流程

1. 上传文件：支持下载模板、上传、取消及下一步。
2. 点击下一步校验：展示共有记录数、可导入记录数、无法导入记录数。共有记录数包含重复数据。存在失败时可下载失败原因说明；无法导入数为0时隐藏该下载入口。可返回上一步修改，也可执行导入。
3. 点击导入文件：只导入校验通过的行；执行过程中展示导入状态，完成按钮不可点击。完成后展示实际成功数、失败数。失败数为0时不显示失败列表；有失败时列出生产用编码、非标点和失败原因，完整展示。

上传校验的“可导入”与执行结束的“导入成功”是不同阶段，不能只看前一个阶段就认定已经创建业务记录。

## 3. 生产用编码与商品校验

同一文件内生产用编码可以出现多次，但生产用编码与非标点的组合不能重复。

| 检查条件 | 失败原因 |
| --- | --- |
| 生产用编码为空 | 当前生产用编码为空 |
| 编码不在商品库 | 当前生产用编码不存在 |
| 编码对应的商品型号不存在 | 当前生产用编码对应的商品型号不存在 |
| 对应商品型号未启用 | 当前生产用编码对应的商品型号未启用 |
| 编码对应多个库内商品型号 | 当前生产用编码对应商品型号不唯一 |
| 对应型号不在账号商品授权范围 | 没有商品权限，添加失败 |
| 编码的信号代码无效、已报废 | 当前生产用编码已报废 |
| 文件内生产用编码＋非标点重复 | 当前生产用编码关联非标点重复 |

**用户已确认正确行可以继续导入。** 例如文件10行，其中2行的生产用编码对应多个商品型号，另外8行正确：这2行校验失败，其余8行仍可导入。原型在该条件下写“数据全部都要视为执行失败”，不能解释为把同文件其他正确行也全部拦截。

## 4. 可选商品型号、商品编码的对应关系

非必填不等于填写后不校验。

| 输入及对应关系 | 失败原因 |
| --- | --- |
| 生产用编码与填写的商品型号不对应 | 当前生产用编码与商品型号不对应 |
| 不同生产用编码对应同一个商品型号 | 当前不同生产用编码存在同一商品型号 |
| 同一个生产用编码对应不同商品型号 | 当前同一个生产用编码存在不同商品型号 |
| 生产用编码与填写的商品编码不对应 | 当前生产用编码与商品编码不对应 |
| 不同生产用编码对应同一个商品编码 | 当前不同生产用编码存在同一商品编码 |
| 同一个生产用编码对应不同商品编码 | 当前同一个生产用编码存在不同商品编码 |

这些检查按原型各项条件保留。原型在“不同生产用编码对应同一个商品型号”处也出现“数据全部”措辞，该关系冲突涉及哪些行应保留关联证据，不能自行从已确认的“库内一个编码对应多个型号”例子扩成所有映射冲突的完整处理算法。正确且不受关系冲突影响的记录允许继续导入，是当前已确认的导入处理原则。

## 5. 非标点及已有组合

非标点名称必填，并且必须存在于非标点名称库。名称不存在时失败原因是“当前非标点不存在”。

**系统已有相同商品编码＋非标点时，该行导入失败，失败理由为“商品机型已有该非标点”。** 不通过这次导入更新原记录的物料、配置状态或其他内容，也不为失败行发起新增或调整审批。

文件内部重复与系统已有记录是两类检查，定位组合和失败原因按各自规则保留，不推断成相同数据库唯一键。

旧用例中的“已有组合更新增减物料”已被用户明确纠正。原型中“已有非标点的创建人不更新”属于与当前重复失败规则不一致的旧片段，不据此恢复覆盖导入。

## 6. 配置状态与增减物料

| 情况 | 处理 |
| --- | --- |
| 没有填写配置状态 | 当前行失败，原因“当前配置状态为空”；不能根据物料自动补状态 |
| 未配置，增加和减少物料都空 | 符合该状态的组合，继续其他校验 |
| 未配置，增加和减少物料均有内容 | 失败，原因“当前配置状态错误” |
| 已配置，增减物料都空 | 允许，其他校验通过即可导入，保留已配置 |
| 已配置，只填一种或两种都填 | 允许相应填写方式，填写的物料继续做有效性和重复校验 |

原型的“增减物料不为空且未配置则失败”还涉及仅一侧有值的解释边界，本次未将尚未单独澄清的细节伪装为用户已确认。旧模板缺配置状态列、枚举外文字的兼容和具体提示见本条未定细节。

填写增加物料、减少物料时，分别与物料库精确匹配：

- 增加物料不存在：当前增加物料不存在；增加物料已报废：当前增加物料已报废。
- 减少物料不存在：当前减少物料不存在；减少物料已报废：当前减少物料已报废。
- 同行增加和减少物料的编码相同：当前物料重复。
- 通过校验后反查物料名称，展示物料编码、物料名称及数量。原型明确减少物料数量未填时按1处理，不能由此推断所有导入字段和所有入口都默认1。

已配置时增减物料可以全空，是用户2026-09-22最新修改，并已经写入现有配置状态知识；此前禁止全空导入的要求作废。有值时仍需有效性校验，配置状态本身仍必填。

## 7. 部分成功与失败明细

校验通过的行计入可导入数，失败行计入无法导入数；执行时只处理可导入行。

例如一个文件7行：
- 第1行未配置，物料都空。
- 第2行已配置，只填增加物料。
- 第3行已配置，只填减少物料。
- 第4行已配置，增减物料都填且编码不同。
- 第5行配置状态空，物料都空。
- 第6行未配置，却填了增减物料。
- 第7行已配置，物料都空。

如果这些行的其他信息正确、目标记录尚不存在，结果为共有7条、可导入5条、无法导入2条。第1～4行和第7行可导入；第5行因状态为空失败，第6行因状态与物料不符失败。第7行不能再按旧非空规则列为失败。

下载失败原因说明包含失败行序号、对应原行的字段内容及失败原因，不混入成功行。配置状态新列在文件中的具体布局、外部模板格式本次没有实测或完整读取，不自行补造。

手工一次添加多条有一条校验失败就全部不提交，是另一入口的规则；不能套用来禁止批量导入中的正确行成功。

## 8. 导入后记录与审批

成功导入后，按生产用编码反查的商品型号、商品编码绑定对应非标点及增减物料；保留用户提交的配置状态。记录按机型非标点维度拆到管理列表，状态为审批中。

按添加型号的审批流程，将完成导入的机型非标点汇总提交到审批表，并按机型非标点维度拆解审批。不能把成功导入等同于审批完成或业务已启用。

类目、系列来自对应机型；创建人和更新人来自本次导入操作人，更新时间为相应导入更新时间。当前重复规则不允许覆盖已有组合，不另定义已有记录创建人更新政策。

## 9. 未定细节与来源

尚未明确的内容单独保留：旧模板缺新列的兼容；配置状态非法枚举的具体提示；未配置且只填一种物料的具体处理表述；部分映射冲突中关联失败行的准确范围；外部模板布局。

非标点必填失败的原型提示写成“当前非标点型号不为空”，有措辞问题。本条保留非标点必填的确定要求，不把该笔误加工成已经确认的新提示。
