# 机型非标点：调整与审批生效

主维护项目：商用订单管理系统-管理端。本条整理“调整”页面的操作条件、配置状态切换、审批前后数据变化及调整记录。依据已读取原型、历史用例和用户确认；不代表已经执行测试。

新增审批被驳回后的“编辑”与现有记录的“调整”是不同入口。本条只规定调整流程；新增驳回编辑沿用原新增审批流的规则，由已发布的添加、编辑与配置状态条目维护。

## 1. 什么时候可以调整

历史操作条件：机型非标点业务状态为待启用、已启用或已禁用，且调整状态为“-”、已通过或已驳回时，可以按权限发起调整。

调整审批正在进行时，不再提供再次调整入口，按权限查看对应调整审批单。不能把配置状态是否已配置当作决定全部操作权限的唯一条件。

点击调整进入当前型号与单个非标点，不提供选择其他型号或添加非标点行的入口。页面展示对应型号、商品编码、生产用编码、非标点、配置状态及增减物料。

调整原型注明生产用编码自26.7.1起改为不可调整；旧版编码修改和同型号联动说明单独保留为历史差异，不作为当前已确认可用的调整功能。

非标点可以按现有选项调整；切换非标点会清空对应增减物料。

## 2. 配置状态怎样操作

| 进入调整前已保存的配置状态 | 页面规则 |
| --- | --- |
| 已配置 | 配置状态显示已配置并置灰，不能改成未配置；不表示整个页面或所有物料都不能编辑 |
| 未配置 | 配置状态可以操作；保持未配置时增减物料为空且禁止填写 |
| 原未配置，临时改选已配置 | 增减物料可以编辑；状态不能因为临时选中已配置就立即锁死 |
| 原未配置，提交前从已配置改回未配置 | 清空增减物料及对应数量，重新禁止填写 |

锁定依据是进入调整前已经保存的值。首次原未配置记录在提交前可来回选择，不等于审批通过后还允许把正式已配置改回未配置。

## 3. 选择已配置时允许不填物料

该规则引用当前已发布条目“机型非标点：已配置时增减物料允许为空”（正文已扩充为添加、编辑与配置状态规则）：

- 未配置改为已配置时，增加物料和减少物料可以同时为空，其他校验通过即可提交调整。
- 原已配置的记录，删除最后一项物料后，两项全空也可以提交调整。
- 不再因上述全空情况提示“当前机型非标点增减物料为空”并阻止提交。
- 填写物料时仍需通过存在性、报废、重复、数量等原有校验。
- 提交空物料申请不等于立即清空正式记录；审批完成前仍使用调整前的数据。

2026-09-22用户最新修改已经替代旧原型和旧确认中的“不能全部为空”，不能在后续知识中恢复该限制。

## 4. 点击确定后的检查

提交时复核必填项、字段格式、商品是否仍存在且启用、非标点是否存在，以及机型与非标点是否重复等条件。具体生产用编码不可调整条件见本条第1节。

全部检查通过且执行成功后提示“机型非标点进入审批流程”，针对本次调整发起新的审批流程。失败时显示相应字段提示或调整失败弹窗；历史弹窗包括序号、商品型号、非标点、失败原因，确定后关闭。

原型组合重复检查没有完整写明如何排除当前记录，不能将“与自身重复”补成必然失败的条件。没有实际修改任何内容是否也能提交，材料尚未明确。

## 5. 审批结束前和结束后分别怎样处理

| 时点或结果 | 调整状态 | 机型非标点数据及业务状态 |
| --- | --- | --- |
| 提交调整成功 | 审批中 | 保持原业务状态和原正式配置、物料；本次申请值尚未生效 |
| 某位中间审批人同意，后面还有审批人 | 审批中 | 不提前更新正式数据，不提前启用 |
| 未配置改为已配置，所有节点全部通过 | 已通过 | 正式配置状态及物料更新为本次获批内容，业务状态为已启用；按相应规则通知订单模块 |
| 原配置已配置、业务状态已禁用，仅调整物料数量，所有节点全部通过 | 已通过 | 用户明确确认仍为已禁用；数量使用本次获批值，不因调整通过自动启用 |
| 任一节点不通过并驳回发起人 | 已驳回 | 原业务状态与正式数据保持，不写入被驳回申请的内容 |
| 调整被驳回后再次发起调整 | 新申请为审批中 | 新增审批单，保留原驳回单；只有后续真正获批的申请才生效 |

引用当前机型非标点的商品，在调整审批尚未完成时使用调整前数据。列表、普通详情按已发布查询与查看规则显示；调整审批单“机型非标点信息”的配置状态已由用户确认为显示调整前值。

用户已经明确“审批全部通过以后才已启用”。因此原型“发起调整后已启用”的句子不能解释成提交即启用。用户还明确了仅改物料数量且原已禁用时仍已禁用，所以不能写成所有调整一律启用。其他未说明的原状态组合保留边界，不从一个例子推定所有情况。

## 6. 驳回后重新调整

重新发起的是新的调整审批单，不覆盖或继续使用上一张已经驳回的调整单。

例如第一次申请增加物料甲被驳回，第二次申请改为减少物料乙：第二次全部审批通过后，应使用第二次获批的内容，不混入第一次被驳回的数据。

这与“新增审批驳回后点击编辑，不新建审批流程”不同，不能统一写成所有驳回重提都新增单据或都沿用原流程。

## 7. 调整记录

既有调整记录包含调整字段、原值、调整后值、调整人、调整时间以及查看审批单。一次修改多个字段时按字段形成多条记录，可关联同一张审批单。审批详情中有本次调整与历史调整两个标签，字段结构相同，按调整时间倒序。

旧资料中调整字段包括生产用编码、非标点、增加物料、减少物料、新增非标点；不同版本出现的旧字段不代表当前仍允许修改该字段。新增非标点的历史记录为原值空、调整后值为非标点名称。

**用户已确认：未配置改为已配置并审批通过后，不需要单独新增一条配置状态原值／调整后值的业务调整记录。** 其他字段既有记录保留，不能解释成禁止内部审计日志。

来源差异必须保留：已读取的调整原型“调整记录内容”字段枚举确实包含配置状态，与用户上述答复不同。当前按用户确认的“不要求单独新增记录”整理，同时明确标注该原型差异，不声称原型没写，也不将差异隐藏。

## 8. 与订单通知的衔接

本次调整涉及未配置改为已配置并且审批全部通过后，向订单管理模块同步本次获批的机型非标点调整信息。详细字段及接收范围由订单关联模块维护。

本条不把某个审批节点通过当作通知生效时点，也不据此声称其他历史调整永远不发通知。只修改数量、原已禁用仍禁用这一用户答复，也不单独决定其他既有通知规则。

## 9. 旧版编码联动说明，仅作历史资料

历史用例和原型残留文字曾规定：修改生产用编码时，查找同型号下编码不等于新值的其他机型非标点；若存在不能调整的条目则失败，否则经确认后联动发起多条调整审批。本条申请失败不应发起其他条目的审批，未改编码不触发联动。

旧不可调整情形包括业务状态待启用／已启用／已禁用且调整审批中，以及业务审批中或已驳回且调整状态为“-”；旧提示为“用户存在不同生产用编码机型非标点审批中”。

由于后续字段表明确生产用编码不可调整，这些旧说明不作为现行已确认操作能力，不恢复成当前流程；如果以后出现明确的新入口，再以对应需求重新核对。
