# 机型非标点：客户端关联与订单通知

主维护项目：商用订单管理系统-管理端。本条说明机型非标点维护对订货及订单模块的已知影响，依据历史用例、当前原型及用户确认；不代表已经执行业务测试。管理端维护及审批规则引用同项目相应条目，不在客户端项目复制整套正文。

## 1. 名称、启用与调整数据的关联

“配置非标点”中编辑名称并保存后，历史规则要求同步关联机型、订货端和管理端。名称同步与本次配置状态变化后的订单通知是两种操作，不能混为同一触发条件。

历史启用规则说明：机型非标点启用后，对应机型可以选择该非标点下单。但仍需满足配置状态和其他下单条件，不能把启用解释为任何情况下都能发起订单。启禁用和删除的条件由“机型非标点：启用、禁用与删除”维护。

调整审批尚未全部通过时，引用该机型非标点的商品继续使用调整前数据；所有节点通过后，正式数据更新为本次获批内容。具体业务状态结果由“机型非标点：调整与审批生效”维护，不能把所有调整都写成自动启用。

这些关联规则不证明客户端具有相同的管理维护页面，也不证明历史订单快照或所有订单状态都跟随主数据更新。

## 2. 未配置时的价格与订单发起

列表原型明确：使用配置状态为“未配置”的机型非标点，订单无法发起，该非标点没有对应价格。

2026-09-22用户已修改规则：选择“已配置”时，增加物料和减少物料可以同时为空。因而订单限制应按实际配置状态判断，不能因为物料为空就认定为未配置。历史记录统一初始化为已配置，也不能按是否有物料另行改成未配置。

“已配置且物料为空允许保存”只说明物料的填写规则，不等于免除其他价格、权限或订单条件，也不能由此保证一定可以下单。

现有材料没有规定客户端选择非标点的控件必须隐藏、置灰或无法选中，也没有定位具体报错按钮或提示文案。本条保留明确的价格及发起结果，不补造控件表现。

## 3. 配置变化何时通知订单模块

本次调整涉及配置状态由“未配置”改为“已配置”，并且审批流所有节点全部通过后，向订单模块推送当前机型非标点的调整修改信息。

- 仅提交调整成功，不代表申请已经生效。
- 中间审批节点通过、但后面还有待审批节点，不提前按获批内容更新正式数据。
- 申请被驳回，不将被驳回内容作为本次已生效变更推送。
- 驳回后重新调整会新增审批单；只有新申请全部通过后，才以新获批内容推送本次配置变更。

列表原型进一步说明，审批通过后的调整单将调整物料编码信息同步至订单管理模块。因此这里包含数据同步，不能改写成只发送一条提醒。

已配置允许增减物料同时为空。材料没有给“未配置改为已配置且物料全空”的获批场景增加免通知条件，不能自行用物料为空取消该配置变更的通知；具体空值传输方式仍需接口约定。

本条明确的是这次配置变化的通知场景，不反向推断其他历史调整一律不推送。原已配置、业务已禁用、仅调整物料数量后仍已禁用的用户确认，也不能单独决定其他既有通知规则。

## 4. 推送信息包含哪些业务字段

| 字段 | 内容 |
| --- | --- |
| 商品型号 | 本次获批记录对应的商品型号 |
| 商品编码 | 对应商品编码 |
| 生产用编码 | 对应生产用编码 |
| 非标点ID | 本次目标非标点标识，不能混用其他非标点 |
| 非标点货期 | 对应记录的实际货期，原型示例“5”不是固定值 |
| 配置状态 | 本次获批后为已配置 |
| 非标点增加物料编码 | 本次获批的增加物料及对应数量语义；“001*2”只是原型示例 |
| 非标点减少物料编码 | 本次获批的减少物料；原型示例空白不表示该字段永远为空 |

推送使用本次获批内容，不能混入旧驳回申请的物料或提交前已清空的临时内容。

上表是业务字段清单，不是已验证的接口参数名或JSON结构。多物料、数量及空值的具体传输格式，现有材料尚未提供。

## 5. 版本差异与未明确范围

旧原型以暂无物料描述未配置背景；现行按用户修改后的“已配置允许物料全空”理解，物料空值与配置状态不能等同。原型中提交调整即启用的旧表述，已由用户确认修正为审批全部通过才生效。

以下内容没有充分材料，不能写成确定规则：

- 哪些现有订单、订单状态、组织或公司接收并应用此次变化，是否修改历史单据快照。
- 接收后是否自动重算金额、如何处理已创建订单，是否需要人工处理。
- 发送失败重试、去重、乱序、重复推送的具体处理。
- 判断接收及应用成功的回执、接口和业务证据入口。

此前笼统的“是否允许下单”和“已有订单自动更新还是人工提醒”追问已撤回；应先定位具体页面与需求，不能要求用户在没有依据的选项中作答。

后续若执行测试，应区分通知已发出、接收成功和订单正确应用；不能仅凭发送成功或HTTP成功认定整条业务链路通过。本条当前仅整理规则，未执行通知或订单测试。
