# 机型非标点：客户端关联与订单通知

状态：本地知识底稿 v0.1，2026-09-21；已有证据覆盖以下关联，客户端完整后续行为尚不具备，未提交预览。

## 历史两端关联

来源：H1-08 名称编辑、H1-13 启用、H1-11 调整。

- 非标点名称编辑保存后，历史规则要求同步关联机型、订货端及管理端。名称同步不等于当前新增配置状态通知，两种变化来源与范围分开。
- 机型非标点启用后，对应机型可选择该非标点下单。
- 调整尚未审批完成时，引用该机型非标点的商品继续使用调整前数据；全部通过后正式数据更新。
- 以上来源不能证明客户端具有相同管理维护页面，也不能证明所有订单状态都允许跟随主数据变化。

## 本期订单通知

来源：F7 第 5.5 条、F9、F10；生效时点 U3 已确认。

触发条件：机型非标点本次调整涉及配置状态未配置→已配置，并且审批流所有节点均通过。向订单模块推送当前机型非标点的调整修改信息。提交成功、某个中间节点通过、被驳回均不能作为本次变更已生效的通知时点。

| 业务字段 | 规则 |
| --- | --- |
| 商品型号 | 当前获批机型对应型号 |
| 商品编码 | 对应商品编码 |
| 生产用编码 | 对应生产用编码 |
| 非标点 ID | 当前目标非标点标识，不能与其他非标点混用 |
| 非标点货期 | 取当前记录的真实值；原型示例 5 不是固定规则 |
| 配置状态 | 本次获批后为已配置 |
| 非标点增加物料编码 | 与本次获批增料对应，包含原型所示数量语义；`001*2` 仅示例 |
| 非标点减少物料编码 | 与本次获批减料对应；原型空白单元格不表示该字段永远为空 |

字段是业务语义清单，不是已经验证的接口字段名或 JSON Schema。空值、数量编码及传输格式以实际接口约定为准，尚未取得。

驳回后重新调整应新增审批单；只有新申请全部通过后，才以新获批内容推送本次配置变更，不能把旧驳回内容当作已生效内容。尚不能反向断言“其他调整一律不推送”，既有其他通知范围未提供。

## 当前不能写成确定知识的内容

- 哪些订单、订单状态、组织或公司在接收范围；是否涉及历史单据快照。
- 客户端应新增哪些字段、提示、可选项限制；未配置时下单是否有额外约束。
- 接收后是否刷新订单物料、货期、价格，是否需要订单审批或人工确认。
- 通知失败重试、去重、乱序和重复推送策略，以及具体证据入口。
- 判断推送成功所需的回执和接收端业务状态。后续测试必须区分“发出通知”“接收成功”“订单正确应用”，不能仅凭发送或 HTTP 成功认定全部正确。

本模块可先整理已明确的发送条件与业务字段，未明的接收政策保留本地待核对；不能为了标题含客户端就自动补齐没有材料的客户端规则。
