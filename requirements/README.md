以用户提供的编号建立目录，不自行发明需求编号。起步只需该目录的 `README.md`，可参考 [需求模板](../templates/requirement.md)。后续有实际内容时增加：

- `sources/`：原始需求、原型或材料索引，标明来源和版本。
- `analysis.md`：业务规则、影响范围、风险、待确认问题及决策记录。
- `cases/`：正式思维导图及必要导出版本，标明当前文件。
- `runs/<日期>-<批次>/`：执行记录、脱敏证据及缺陷关联。
- `knowledge-sync.md`：知识库目标项目、条目引用、版本和同步结果。

同一个需求涉及两端时不拆成相互独立的需求目录。阶段结束更新入口状态，已有缺陷平台时优先记录其编号和链接，避免维护互相矛盾的缺陷副本。
