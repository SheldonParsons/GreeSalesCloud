# 统一入口、查询查看与简洁回执对照

2026-10-28用户授权实现统一调用入口、查询查看组合流程、简洁回执，并做耗时和Token对照。实现见[runtime说明](../runtime/README.md)，脱敏数据见[summary.json](../../governance/runs/20261028-ui-entry/summary.json)。

## 实现范围

- `tools/run.mjs`统一校验、准备连接/页面、执行并返回简洁JSON；运行库可复用调用方的持久MCP连接。
- 新增`query-and-read-child@0.1.0`，复用`read-child-detail@0.1.1`。后者仅增加只读调用声明，函数源码未变，详情实现没有复制。
- 目录共5项能力，新入口只接入其中2项只读能力，未接入填表、审批和接单。
- 完整快照、源码调用参数和详细响应留在本机，正常模型只收到结论、断言汇总及证据入口。

## 对照口径

同一个Chrome 156无界面会话、QA客户端账号、既有子单、1728×803视口和DPR 2，两种方式执行相同15项断言。各预热一次，再各测三次，顺序为基线→优化、优化→基线、基线→优化。

基线是逐步MCP调用：页面检查、获取控件、原生重置、等待、重新取得控件、原生输入、原生查询、列表核验、详情核验，共9次。组合方式合并已验证的准备步骤，在主机端解析快照，保留原生输入/查询点击及相同详情核验，共6次。

计时包含就绪页面中的执行段，新入口也包含回执持久化；不包含浏览器启动、认证、共同关闭上一轮详情、截图、离线分词和模型思考/调度等待。不是完整Agent任务的墙钟时间。

## 有效结果

| 指标（每次流程，中位数） | 逐步调用基线 | 统一组合入口 |
| --- | --- | --- |
| 执行段耗时 | 2753.65毫秒 | 2520.87毫秒 |
| 底层MCP调用数 | 9 | 6 |
| 投影到模型的回执字符数 | 24122 | 423 |
| 回执文本估算Token | 11089 | 139 |
| 实际断言 | 15项通过 | 15项通过 |

小样本中执行段中位数约少8.5%，底层调用少33%。网络和页面异步行为仍有波动，不作统计显著性或所有场景提速承诺。

Token使用`js-tiktoken@1.0.21`、固定`o200k_base`，对JSON序列化后的工具返回文本离线计数：基线假定逐步MCP回执全部进入模型，优化只计summary。输出文本估算量约少98.7%；这**不是Codex实际usage、计费用量或费用下降比例**，不包含系统提示、历史上下文、工具定义、调用输入、思考、图像及缓存计费。若旧流程已在主机端批处理或裁剪输出，收益会更小。

优化内部仍处理约19634字符的MCP响应。这些数据保存在主机侧，并未删除；需要排障时按回执和失败步骤读取。

- 两种方式的15项断言结果一致，详情截图已查看。未创建、修改、审批咨询单，未更改Mind或BUG。
- 联调发现整段header为`CCQRain03`（头像C紧邻昵称），已改为精确核对独立可见账号节点；近似账号仍被拒绝。
- 抽屉遮罩有退出过渡，准备阶段保留有界可操作性等待，不跳过遮挡检查。
- 纯脚本点击查询未取得目标结果，最终保留MCP原生输入和查询点击；未把其内部事件原因当作已定位产品缺陷。
- 这些准备失败留有本机诊断，未计入有效样本；没有为提速放宽业务预期或详情核验。
- 另以命令行批次连续执行同一目标两次，15项断言均通过且截图实际落盘，验证批次内连接复用。该验收含截图，各有7次底层调用，不混入上表。其前一次启动曾在认证准备阶段遇到网络错误，未执行能力，保留为阻塞，不作为性能样本。
- 仅验证一个账号和单据，未验证跨目标遗留抽屉、并发、其他环境或业务写入。bootstrap示例仍依赖外部GreeProject，不冒充跨平台认证能力。

复现入口为`tools/benchmark-query.mjs --request <本机JSON> --bootstrap <本机模块>`，TypeScript认证依赖按runtime说明加载。`--development`仅用于已授权的未发布只读能力验证，日常入口默认要求能力已验证。原始调用、截图和回执位于本机`.local/ui-entry-benchmarks/`及`.local/ui-runs/`，不进入Git。
